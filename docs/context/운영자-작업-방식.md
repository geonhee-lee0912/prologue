# 운영자 작업 방식

에이전트(Claude Code·Codex)가 운영자와 일할 때 따르는 방식이다. 2026-10-15 프롤로그 컴퓨터의 Claude 자동 메모리와 지난 대화 기록에서 옮겼다(멀티 서비스 플랫폼 스펙 10장 1단계).

- 1–4장은 서비스와 상관없다. `platform` 저장소가 생기면 그쪽으로 옮기고 여기에는 요약과 링크만 남긴다(같은 스펙 10장 3단계). 5장은 프롤로그에만 해당한다
- 저장소에 없는 맥락은 없는 것으로 친다. 새 결정은 해당 작업 브랜치의 `docs/decisions/`에 남기고, 관련 안내에는 근거를 연결한다. 진행 상태는 브랜치의 HANDOFF.md가 정본이다

## 1. 대화

- 한국어로 쓴다. 운영자 메시지는 짧고 오타가 많다. 뜻을 읽어서 움직이되, 무엇과 무엇을 비교하라는 건지처럼 핵심이 헷갈리면 먼저 확인한다. 2026-10-14 "그록 봇·GPT 닷과 비교해 봐"는 갈피가 아니라 운영자가 그리는 원격 개발 환경 구조와 비교하라는 뜻이었다
- 선택지를 낼 때는 추천안을 먼저, 이유와 함께 낸다. 운영자는 대개 추천안을 고르지만 "추천안은 킵하고 다른 것도 보자"처럼 갈래를 더 볼 때가 있다
- 정할 것이 여럿이면 한 번에 하나씩, 자세히 설명하고 선택지를 붙인다("나머지도 하나씩 부수자. 자세히 설명해 주고 선택지를 한 문항씩")
- 설명이 어렵다는 반응이 오면 운영자가 이미 쓰고 있는 것과 견줘 다시 설명하거나(예: 지금 별콩톡 구성과 비교해 무엇이 달라지는지) 구조도로 그린다
- 서비스·도구를 조사할 때는 가격, 장단점, 우리 구조에서의 예상 비용을 같이 낸다. 조사한 날짜와 출처를 남기고, 원화인지 달러인지와 부가세 포함 여부를 밝힌다

## 2. 일하는 순서

- **큰 범위부터 잡는다.** 전체 구성·위계·남은 일의 지도를 먼저 만들고 세부로 들어간다("다 아니고 전체 서비스 구성, 위계부터 잡자", "작업 전에 전체적인 깃헙 레포 구성과 별콩톡에서 해야 하는 작업 먼저 정리해 줘")
- **외부 리서치(사용자 인터뷰 등)는 하지 않는다.** 만들어서 검증한다
- **BM 과 원가를 늘 같이 본다.** AI 가 붙으면 쓸수록 적자가 커질 수 있다. 기능을 제안할 때 AI 호출 원가와 SaaS 비용을 함께 적는다
- **보안·운영 차단 항목은 바로 고치지 않고 출시 전 최종 점검에서 한꺼번에 처리한다. 대신 반드시 기록한다**(프롤로그는 `BACKLOG.md` 9절). 새 코드는 같은 문제를 늘리지 않는다(같은 절 "앞으로 새 코드에서 지킬 것")
- 운영자는 세션을 자주 끊고 이어 간다("여기까지만 하고 나중에 이어서", "이거 새로운 세션에서 하자"). 멈출 때는 상태와 다음 할 일을 해당 브랜치의 HANDOFF.md에 남겨 커밋·푸시한다. 작업 순서는 ROADMAP.md, 상세는 BACKLOG.md를 따른다([인계 안내](에이전트-인계.md))
- 운영자가 이미 정한 것은 다시 묻지 않는다. 예: 앱 먼저·화면 먼저(2026-09-11·17, 컨셉 문서 11장), 첫 지역·직군은 나누지 않음(2026-10-11)
- 문서끼리 부딪히면 "우선 문서" 규칙을 기계적으로 적용하기 전에 날짜와 변경 이력을 비교한다. 더 최근 문서에 운영자의 분명한 결정이 있으면 그것이 결정이고, 낡은 문서는 고치자고 제안한다. 2026-10-06 당시 CLAUDE.md의 우선 규칙만 보고 이미 버린 웹 검증안을 다시 꺼냈다가 지적받았다

## 3. 허락받고 할 것

- **생성 작업(이미지·영상 등).** 매 라운드마다 무엇을, 어떤 모델·프롬프트로, 몇 장, 크레딧 얼마로 만들지 먼저 말하고 분명한 yes 를 받은 뒤 만든다. 방향에 대한 의견("배경은 중요하지 않아")은 실행 승인이 아니다. 앞 라운드의 승인은 다음 라운드로 이어지지 않는다. 2026-10-09 갈피 시안 2차를 의견만 보고 바로 만들었다가 지적받았다("만들기 전엔 항상 뭘로 만들겠다고 허락받고 만들어")
- **푸시.** 별도 요청이 없으면 운영자가 확인한 뒤 한다. PR 생성·푸시를 명시적으로 요청한 작업은 해당 브랜치 게시까지 승인된 범위로 보고 다시 묻지 않는다. 커밋은 주제별로 나눈다
- **DB 에 적용하는 일.** `prisma migrate deploy`, `pnpm db:rls`, `supabase db push` 는 사람이 확인한 뒤 한다
- **합치기와 운영 콘솔.** 에이전트는 이슈와 PR 까지만 만들고 합치기는 사람이 한다. 자동 병합을 켜지 않는다. 운영 콘솔(Vercel·Supabase·토스) 열쇠는 에이전트에게 주지 않는다(멀티 서비스 플랫폼 스펙 9장)
- **계정 만들기.** GitHub 조직, 외부 서비스 가입·계약, 결제는 운영자가 직접 한다

## 4. 디자인 취향 — "AI 가 만든 느낌" 금지

운영자는 화면이 AI 가 찍어낸 것처럼 보이는 것을 싫어한다.

- 기본값으로 꺼내지 않는 것: 파스텔(라벤더·하늘·로즈), 웜·크림·베이지 바탕, 명조(세리프) 글꼴. 크림 바탕에 명조는 AI 제품 화면과 같은 조합이고, 라벤더 파스텔은 요즘 AI 제품에서 가장 흔한 색이다. 2026-10-11 팔레트를 고르며 운영자가 차례로 뺐다("너무 파스텔 톤이라 AI 가 디자인한 느낌", "웜 자체도 인공지능 느낌", "폰트는 무조건 고딕 - 프리텐다드")
- 출발점: 흰 바탕 모노톤, 회색 상자, 먹색 버튼, 강조색은 표시에만. 글꼴은 Pretendard. 따뜻함은 색이 아니라 캐릭터·사진 같은 콘텐츠로 낸다. 카톡처럼 익숙한 구조와 테마형 배경 아이디어는 좋아했다
- 캐릭터의 말은 친구 같은 쪽에서 출발한다. "인터뷰"는 딱딱하고 해요체는 상담원 같다고 했다(갈피는 반존대, 때가 되면 말 놓기). 단 버튼·동의·결제 같은 시스템 문구는 담백한 해요체로 쓴다
- 프롤로그의 값은 `apps/mobile/theme/tokens.ts`(코랄은 표시에만), 근거는 `docs/superpowers/specs/2026-10-10-서비스-구성-위계-design.md` 10.6, 갈피 말투는 `docs/superpowers/specs/2026-10-09-브랜드-세계관-갈피-design.md` 3.6

## 5. 프롤로그 진행 방향 (2026-10-11부터)

- 지금 할 일은 AI 엔진과 화면 고도화로 제품 완성도를 높이는 것이다. BM(연결권·리포트 가격, 차감 규칙)은 그 과정에서 함께 설계한다. 근거는 컨셉 재설정 문서 11장의 2026-10-11 메모
- 갈피 AI 엔진 1단계(소개 전)는 2026-10-14 에 끝났다. 실행 중 결정은 `docs/superpowers/plans/2026-10-11-갈피-AI-엔진-1단계-결정.md`, 남은 일은 `BACKLOG.md` 10절
- **공통 기능 현황 조사·현황표 작성 계획은 폐기됐다(2026-10-30). 공통 플랫폼 계획 전체는 유지한다.** 조사나 현황표 승인을 선행 작업으로 다시 넣지 않는다. 공통 작업 우선 방향과 `platform`·`ops`·`notify` → `notify` 연결 순서는 유지하며, 별콩톡 보안 수정은 기다리지 않는다. 프롤로그 자체 기능 개발은 기존 결정대로 연결 뒤 재개한다(멀티 서비스 플랫폼 스펙 14장)
- 그 뒤 다음 작업을 제안할 때는 갈피 엔진 다음 단계(모바일 연결, 진입 흐름의 동의 3종·본인인증, 진짜 LLM 켜기 전 점검)와 화면 고도화(페이지별 구체화)를 중심에 둔다. 시장 진입·세분화·리서치 과제는 먼저 꺼내지 않는다
- 새 테이블은 RLS 와 정책 테스트를 같이, 외부 서비스는 진짜/mock 스위치와 운영 가드를 같이 만든다
- 별콩톡·프롤로그·앞으로의 서비스가 같이 쓰는 구조는 `docs/superpowers/specs/2026-10-15-멀티서비스-플랫폼-design.md`(v0.6)에 있다. Railway 는 쓰지 않고 Vercel + Supabase 로 간다. Claude Max 5x·ChatGPT Pro 는 구독 시작일에 개인 계정으로 함께 시작한다(지금 두 컴퓨터의 Claude 는 회사 계정)

클라우드 작업은 데스크톱을 켜 두거나 로컬 메모리를 읽는 데 의존하지 않는다. 비밀값 없이 편집·테스트·푸시하며, 로컬 전용 작업을 HANDOFF에 구분한다. 작업 지침은 루트 `AGENTS.md`, 현재 순서는 `ROADMAP.md`를 따른다. 5장의 이전 순서 설명이 현재 ROADMAP을 대신하지 않는다. 2026-10-17에 적은 계정·구독 상태는 당시 기록이며 현재 실제 상태로 단정하지 않는다.

## 변경 이력

- 2026-10-31: 중단·교대 기록을 HANDOFF, 순서를 ROADMAP, 결정을 docs/decisions로 구분하고 클라우드 비밀값 0을 반영했다.

- 2026-10-30: 현황 조사·현황표 계획의 폐기 범위, 클라우드 실행, 요청된 PR의 브랜치 게시와 자동 병합 금지를 반영했다.

- 2026-10-17: 5장에 공통 작업이 먼저라는 순서와 구독 결정
- 2026-10-15: 처음 씀. 프롤로그 컴퓨터의 메모리(제품 진행 방향, AI 느낌 디자인 금지, 생성 전 허락, 앱 먼저 결정의 교훈)와 대화 기록에서 옮겼다
