# 0. 이 문서의 목적

"갈피 대화 설계"를 위에서부터 잡는다. 인터뷰 문항 같은 세부를 먼저 정하지 않고, **AI 엔진 전체가 무엇으로 이루어지고 무엇을 만들며 누가 보고 언제 도는지**를 먼저 정한다. 조각별 세부(인터뷰 문항, 프롬프트 문구, 리포트 문장)는 고도화하며 채운다(13장).

이미 정해진 것은 다시 정하지 않고 따른다 — 갈피의 성격·말투·하는 것과 하지 않는 것·상황별 행동(갈피 문서 3.3~3.6), 하드룰 8가지, 민감정보·국외이전·가명처리 규칙(CLAUDE.md 10장·13장), 모델 GPT-5.6 Luna.

| 본인인증 | **본인인증을 해야 모든 기능을 쓴다.** 인터뷰도 인증 뒤. 본인인증 전 임시 참여자(`Participant`)는 두지 않는다 (9장) |
| 조건 정보 증빙 | **선택.** 본인이 편지에 담기로 허락한 항목에만 "확인됨". 원본은 확인 뒤 폐기. 방식은 편지(D1) 설계 때 (10장) |
| 리포트 | **첫 리포트는 무료(인터뷰를 마치면), 갱신은 단건 유료.** 리포트를 사도 소개에는 아무 영향이 없다 (6장) |
| 만드는 순서 | 1단계 소개 전 → 2단계 소개 시작 → 3단계 배움이 쌓인 뒤 (2.4) |

# 2. 엔진 지도

## 2.1 조각

| 조각 | 하는 일과 만드는 것 | 누가 보나 | 언제 도나 |
|---|---|---|---|
| **① 대화** | 갈피가 말하고 듣는다 — 첫 만남, 인터뷰, 매일 대화, 사건별 대화(편지 전달·넘긴 이유·서로 수락·만난 뒤·편지 없는 기간), 상담. 갈피의 말과 표정 번호를 만든다 | 본인 | 실시간 |
| **② 갈피의 서고** | 들은 말을 사용자별 위키로 정리한다 — 장(페이지), 구조화 칸(실용 정보, 조건 정보와 편지 허락), 취향 | AI만. 본인은 보이는 장을 "갈피가 기억하는 것"에서 보고 뺄 수 있다 | 대화 뒤 |
| **③ 주선** (2단계) | 편지를 쓸지 정한다 — 규칙·임베딩으로 거른 뒤 AI가 마지막 판단, 기준 미달이면 쓰지 않는다. 가벼운 소개 상대도 고른다 | 아무도. 점수는 어디에도 나가지 않는다 | 정기 배치 |
| **④ 글쓰기** | 서고 밖으로 나가는 글 — 리포트(1단계), 편지·이야기 한 줄(2단계), 갈피가 발견한 것·서고 일지(3단계) | 편지는 상대, 나머지는 본인 | 사건 뒤 |
| **⑤ 먼저 말 걸기** | 갈피가 먼저 다가갈 때 — 하루 한 번 이하, 이어하기 1회, 만난 다음 날 1회, 티 나지 않는 알림 문구 | 본인 | 예약 |
| **⑥ 공용 위키** (3단계) | 여러 사람의 서고와 만난 뒤 이야기에서 **경향**만 모은다 | 갈피의 권유, 주선, 나중의 상담 친구가 읽는다. 사람에게 그대로 보이지 않는다 | 배치 |
| **바닥** | 모든 조각이 지나는 길 — 가명처리, 민감정보 마스킹, 위기 신호, 금지 표현 검사, AI 고지, 결정 설명 기록, 진짜/mock 스위치, 캐싱, 원가 감시, 평가 세트 (8장) | — | 항상 |

## 2.2 도는 순서

```
대화 → 서고(수집) → 주선 → 편지(글쓰기) → 답(수락 / 넘김)
  ↑                                          ↓
  │                       넘긴 이유를 듣는 대화 → 서고
  │                                          ↓
  └── 발견·리포트 갱신 ← 서고 ← 만난 뒤 대화 ← 만남
```

컨셉 4.5의 핵심 루프("깊게 말한다 → 주선이 좋아진다 → 만난다 → 어땠는지 말한다")가 엔진 안에서는 이 모양이 된다. 넘긴 이유와 만난 뒤 이야기는 서고의 "끌리는 것과 아닌 것"으로 들어가 다음 주선을 바꾼다.

## 2.3 엔진 밖

- **사람 대화방**: AI가 읽지 않는다. 학습·분석에 쓰지 않고 신고가 들어왔을 때만 사람이 연다(컨셉 5.6). "대화 성립" 판정은 내용이 아니라 메시지 수로 한다
- **상담 친구의 방**(나중): 기록하지 않는다(IA 10장). 그래서 서고로도 공용 위키로도 들어가지 않는다
- **운영자**: 주선에 관여하지 않는다(하드룰 7). 자동화된 결정의 설명·거부 요청이 오면 사람이 대응한다(CLAUDE.md 10.2d)

## 2.4 만드는 순서

| 단계 | 조각 | 왜 이때 |
|---|---|---|
| **1단계 — 소개 전 (지금)** | ① 첫 만남·인터뷰·매일 대화·사용자가 먼저 거는 대화, ② 서고(보이는 장·구조화 칸), ④ 리포트, ⑤ 하루 한 번·이어하기, 바닥(결정 설명 기록은 2단계) | 컨셉 11장 "단계 0+1"(앱 AI 인터뷰 + 리포트) 검증에 필요한 만큼. 상대가 0명이어도 작동한다 |
| **2단계 — 소개 시작** (사람이 충분히 모인 뒤) | ③ 주선, ④ 편지·이야기 한 줄, ① 사건별 대화, ② 끌리는 것과 아닌 것(넘긴 이유·만난 뒤로 배우기), 바닥의 결정 설명 기록 | 밀도 임계치 전에 소개를 열면 나쁜 첫인상만 남는다(컨셉 11장) |
| **3단계 — 배움이 쌓인 뒤** | ⑥ 공용 위키, ④ 갈피가 발견한 것·리포트 갱신·서고 일지, 가벼운 소개에서 취향 배우기, 상담 친구 | 경향은 여러 사람이 쌓여야 생긴다 |

# 3. 갈피의 서고 — 사용자별 위키

## 3.1 왜 위키인가

카파시의 LLM 위키 패턴(2026-04)을 쓴다. 질문이 올 때마다 원문을 검색하는(RAG) 대신, **LLM이 원문을 읽어 서로 연결된 위키로 정리해 두고 새 원문이 올 때마다 고쳐 쓴다.** 세계관의 서고(갈피가 들은 이야기를 서가에 정리해 두는 기록관)가 곧 이 구조다.

얻는 것

- **기억의 일관성** — 몇 달이 지나도 갈피가 같은 사람을 기억한다. "산책 얘기에 갈피가 끼워져 있어요"가 위키의 "다음에 꺼낼 것"에서 나온다
- **원가** — 매 턴 긴 대화록 대신 짧은 위키를 넣는다. 갈피의 고정 프롬프트 뒤에 붙어 캐싱과 맞는다
- **주선** — 정리된 이해끼리 비교하므로 판단이 싸고 일관된다
- **화면** — 내 이야기 탭의 책장(장)이 위키 페이지다. 열람·삭제권과 결정 설명이 위키 위에서 자연스럽게 된다
- **리포트** — "제가 읽은 당신"은 위키를 편지로 옮긴 것이다

## 3.2 세 층

| 층 | 무엇 | 비고 |
|---|---|---|
| **원문** | 갈피 대화방의 말, 넘긴 이유, 만난 뒤 이야기, 취향 카드 선택 | 고치지 않는다. 저장할 때 민감정보 마스킹(8장). 사람 대화방과 상담 친구 방은 넣지 않는다 |
| **위키** | 사용자마다 장 몇 개와 구조화 칸 | 갈피가 쓴다. 문장마다 출처(어느 원문)와 날짜 |
| **규칙** | 어떤 장이 있고, 어떻게 쓰고, 무엇을 쓰지 않는지 | 엔진 코드와 프롬프트에 둔다 |

## 3.3 장 구성과 보이는 범위

| 장 | 담는 것 | 본인에게 |
|---|---|---|
| 요즘의 나 | 일상, 리듬, 취미, 일, 요즘 마음 | 보임 |
| 사람들 | 가족, 친구, 친구들이 보는 나 | 보임 |
| 바라는 관계 | 연락 빈도, 다툼을 푸는 방식, 함께 하고 싶은 것 | 보임 |
| 만난 뒤 이야기 (2단계) | 만남마다 **내 경험**. 상대를 알아볼 수 있는 정보는 적지 않는다 | 보임 |
| 끌리는 것과 아닌 것 | 말한 취향과, 넘긴 이유·만난 뒤에서 드러난 취향 | **AI만.** 본인에게는 "갈피가 발견한 것"(3단계)으로 다듬어서만 |
| 다음에 꺼낼 것 | 다가오는 일, 하다 만 이야기("금요일 발표") | AI만 |
| 목차와 바뀐 기록 | 장 목록, 언제 무엇이 바뀌었나 | 결정 설명용 |

앞의 세 장은 지금 mock 책장(첫 장 — 요즘의 나 / 두 번째 장 — 나를 둘러싼 사람들 / 세 번째 장 — 내가 바라는 관계)과 맞는다. 장은 고정된 틀로 시작하고, 자유 페이지는 쓰임이 보이면 연다.

## 3.4 구조화 칸

위키 글이 아니라 칸으로 둔다. 편지에 무엇이 들어가는지 분명해야 하기 때문이다.

| 칸 | 예 | 편지에 |
|---|---|---|
| 실용 정보 | 생활권, 나이, 흡연, 결혼 의향 | 들어감 |
| 조건 정보 | 학교, 연봉(구간), 주거 형태, 회사 | **본인이 허락한 항목만**(하드룰 8). 항목마다 허락 여부와 확인(증빙) 여부를 함께 둔다 |
| 동의한 민감정보 | 종교 | 매칭에만. 민감정보 별도 동의 범위 안에서(CLAUDE.md 10.2b) |

## 3.5 수집·질의·점검

- **수집**: 말 하나마다가 아니라 **대화가 한 덩이 끝날 때** 돈다 — 인터뷰의 한 장, 매일 대화가 멈춘 뒤, 사건 대화가 끝난 뒤. 비동기(패턴 4). 매일 대화의 수집은 **하루 한 번 이하, 새 내용이 있을 때만, 배치 단가로** 돌린다. 저장 전에 민감정보·다른 사람을 알아볼 정보·금지 표현을 검사한다
- **질의**: 대화는 목차 + 관련 장 몇 개 + 다음에 꺼낼 것을 읽는다. 리포트는 보이는 장 전체를 읽는다. 주선과 편지(2단계)는 장 요약과 취향을 읽는다
- **점검**: 사용자마다 주기적으로 돈다 — 모순을 시간 순으로 정리("예전엔 자주 걸었는데 요즘은…"), 새어 든 민감정보 제거, **출처 없는 문장 제거**(요약의 요약으로 생기는 왜곡 방지), 장 길이 지키기

## 3.6 갈피 빼기와 결정 설명

- **갈피 빼기**: 사용자가 "갈피가 기억하는 것"에서 문장을 빼면 그 문장과 **출처 원문까지** 지운다. 갈피 문서 3.6 ①의 "갈피를 빼면 그 장은 다시 펼치지 않아요"가 기술적으로 사실이어야 한다
- **틀린 것 고치기**: 사용자가 "이건 틀렸어요"라고 하면 갈피가 그 문장을 고친다. 왜곡을 막는 가장 확실한 장치다
- **결정 설명** (2단계): 편지를 쓸 때 근거가 된 위키 문장을 기록해 둔다. 설명 요청이 오면 사람이 그 기록으로 답한다(CLAUDE.md 10.2d)

## 3.7 원문 보관

- **탈퇴할 때까지 보관한다.** 그 전에는 "갈피 빼기"로만 지운다. 위키를 다시 정리하거나 점검할 때 원문과 대조할 수 있다
- 처리방침에 "회원 탈퇴 시까지"로 적는다. 탈퇴할 때 실제로 파기하는 일은 `BACKLOG.md` 9절(지금은 탈퇴가 상태만 바꾼다)과 함께 출시 전에 처리한다
- 보관 기간은 출시 전 법률 자문에서 다시 본다

## 3.8 지킬 것

- **하드룰 2**: 위키는 어떤 사용자에게도 가지 않는다. 편지는 위키에서 **해석**만 뽑고, 조건은 허락한 항목만 담는다
- **넘긴 이유**: 넘긴 이유에서 나온 문장은 본인 화면에도 그대로 보이지 않는다(CLAUDE.md 7.3). 장마다 보이는 범위를 둔 이유다
- **다른 사람**: 만난 뒤 이야기는 내 경험으로만 적는다
- **외모 신호**: 그 사람의 매칭에만 쓰고 전체 노출 순위에는 쓰지 않는다(CLAUDE.md 13장 공정성)

# 4. 공용 위키와 상담 친구 (3단계·나중)

## 4.1 공용 위키

여러 사람에게서 나온 **경향**을 모은 위키다. "첫 대화에서 질문을 하나씩 돌려주는 분들이 다음 만남으로 잘 이어졌어요" 같은 것. 갈피 문서 3.6 ②의 "다른 사람들에게서 배운 권유"의 재료이고, 주선의 경험칙이 된다.

들어가는 조건 — 갈피 문서 3.6 ②의 세 조건을 위키 규칙으로 옮긴다

1. **여러 사람에게서 나온 경향만.** 최소 인원은 정한다(13장)
2. **원문 인용과 개인을 알아볼 수 있는 문장은 넣지 않는다.** 넘긴 이유의 원문은 들어가지 않고 경향만 들어간다
3. **특정 소개·특정 시점과 연결하지 않는다.** 외모에 관한 경향은 사용자가 먼저 물을 때만 꺼낸다

처리방침에 "여러 사람의 대화에서 익명 경향을 배워 소개와 조언에 쓴다"를 목적으로 적는다. 법률 확인 목록에 올린다.

## 4.2 상담 친구 (신규 캐릭터, 나중)

공용 위키를 잘 모아 두면 **연애 상담 캐릭터**가 이것을 바탕으로 이야기할 수 있다. IA 10장의 "상담 친구"다.

- **서고를 읽지 않는다.** 서고 규칙 1 — "당신의 이야기는 갈피만 읽는다"(갈피 문서 2.4)
- 읽는 것은 **공용 위키 + 자기 방에서 들은 것**뿐이다
- 자기 방 대화는 기록하지 않으므로 공용 위키로 되돌아 들어가지 않는다. 읽기만 하는 친구다
- 위기 신호는 어느 방에서든 똑같이 안전 안내로 넘어간다(IA 10장)

# 5. 대화 지도 (큰 틀)

## 5.1 대화 종류와 시점

| 언제 | 어떤 대화 | 누가 먼저 | 얼마나 | 서고에 채우는 것 |
|---|---|---|---|---|
| 본인인증 직후 | **첫 만남** — 자기소개, 사람이 아니라는 것, 서고 규칙 하나, 가벼운 질문 하나(갈피 문서 3.6 ③) | 갈피 | 1분 | — |
| 첫날~며칠 | **인터뷰 세 장** — 요즘의 나 / 사람들 / 바라는 관계 | 갈피 | 장마다 4턴 안팎, 합쳐서 12턴 이상·최대 30턴(`POLICY.interview`) | 보이는 세 장 |
| 인터뷰 중 일 이야기 뒤 | **조건 정보** — 학교·연봉·주거·회사. 항목마다 "편지에 적어도 될까요?" | 갈피 | 항목당 1~2턴. 건너뛸 수 있다 | 구조화 칸 + 편지 허락 |
| 인터뷰를 멈췄을 때 | **이어하기** — "지난번엔 여기 끼워 뒀어요" | 갈피 | 24시간 뒤 한 번만 | — |
| 세 장을 마치면 | **리포트 편지** "제가 읽은 당신" (6장) | 갈피 | 편지 한 통 | — |
| 그 뒤 매일 | **매일 대화** — 기억 하나를 꺼내고 질문 하나로 끝낸다 | 갈피 | 하루 한 번 이하, 2~3턴 | 요즘의 나 갱신, 다음에 꺼낼 것 |
| 아무 때나 | **사용자가 먼저** — 상담, "요즘 왜 편지가 없어?", 범위 넓혀 보기, 잡담 | 사용자 | 제한 없음 | 관련 장 |
| 편지가 오면 (2단계) | 편지를 건네는 한 줄 → 넘기면 이유를 한 번 → 서로 수락이면 짧게 기뻐한다 | 갈피 | 각 1~2턴 | 끌리는 것과 아닌 것 |
| 만난 다음 날 (2단계) | "어제 만남은 어땠어요?" | 갈피 | 한 번만 묻고, 답하면 3~8턴 | 만난 뒤 이야기, 끌리는 것과 아닌 것 |
| 언제든 | **위기 신호** → 세계관을 거두고 안전 안내 (8장) | — | 바로 | — |

## 5.2 기본으로 고른 것

1. **인터뷰는 장 단위로 끊을 수 있다.** 한 번에 다 해도 되고 하루에 한 장씩 해도 된다. 한 장이 끝날 때마다 책장에 꽂히고 "계속할까요, 여기 끼워 둘까요?"를 묻는다. 소개는 세 장을 다 마쳐야 시작한다 — 남성 쪽의 "성의 검증"(컨셉 5.9)이 완주 기준으로 유지된다
2. **조건 정보는 인터뷰 안에서, 일 이야기 뒤에 묻는다**(갈피 문서 3.6 ③). 허락은 버튼 두 개("적어도 돼요" / "서고에만 둘게요")로 받아 기록을 분명히 한다. 증빙은 원하는 사람에게 "확인해 둘까요?"로 이어 준다(10장)
3. **갈피가 먼저 말을 거는 것은 하루 한 번 이하**(`POLICY.galpi.proactiveMessagesPerDay`). 시간은 그 사람이 주로 대화하던 시간대로 하고 **밤 9시~아침 8시는 피한다.** 답이 없으면 다음 날 같은 것을 다시 묻지 않는다(하드룰 6)

## 5.3 세부로 미룬 것

인터뷰 문항과 장별 깊이, 턴 수 조절 규칙, 매일 대화의 소재를 고르는 규칙, 사건별 대화의 문구, 상담의 범위. 조각별로 고도화할 때 정한다(13장).

# 6. 글쓰기 — 1단계는 리포트

| 글 | 단계 | 읽는 것 | 지킬 것 |
|---|---|---|---|
| **리포트 "제가 읽은 당신"** | 1 | 보이는 장 전체 | 단정하지 않는다, 평가·점수 없음, 민감정보와 넘긴 이유 기반 내용은 쓰지 않는다, "이 편지는 AI가 썼어요" 표시 |
| 편지 "왜 이 분인가"·이야기 한 줄 | 2 | 두 사람의 장 요약 | 원문 대신 해석만, 조건은 허락한 항목만(하드룰 2·8), 근거 문장 기록(3.6) |
| 갈피가 발견한 것 | 3 | 끌리는 것과 아닌 것 | 관찰로 말하고 훈계하지 않는다(갈피 문서 3.6 ②-2), 특정 소개와 연결하지 않는다 |
| 서고 일지·상태메시지 | 3 | 공용 정보만 | 다른 사용자가 나오지 않는다(IA 3.3) |

**리포트 BM**: 인터뷰를 마치면 첫 리포트를 **무료로** 준다(완주를 끌어내는 장치). 매일 대화와 만남이 쌓여 서고가 자라면 **갱신을 단건으로 판다**(컨셉 6.3, 화면 흐름 C3). 가격과 갱신 주기는 13장. **리포트를 사도 소개에는 아무 영향이 없다** — 무료 사용자가 소개에서 밀리는 구조 금지(CLAUDE.md 16장).

# 7. 먼저 말 걸기

- **하루 한 번 이하**, 밤 9시~아침 8시 제외
- **이어하기**: 인터뷰를 멈추고 24시간 뒤 한 번만(`POLICY.interview.resumeReminderHours`, `resumeReminderMaxCount`)
- **만난 다음 날** 한 번(2단계). 답이 없으면 다시 묻지 않는다
- **소재**: 다음에 꺼낼 것 → 서고의 빈칸 → 취향 카드 순
- **잠금화면 문구는 티 나지 않게**: "갈피: 어제 발표는 잘 끝났어요?" — 상대 정보·소개팅이라는 말을 넣지 않는다(IA 3.11)
- **죄책감 문구 금지**: "왜 안 와요", "기다리고 있어요"(CLAUDE.md 9.1)
- 예약 작업으로 돈다(데이터 흐름 패턴 4, BullMQ). 푸시는 `PushProvider` 인터페이스를 거친다(CLAUDE.md 11장)

# 9. 본인인증과 진입 순서

```
가입 → 동의(필수 / 민감정보 별도 / 국외이전 별도) → 본인인증 → 갈피 첫 만남
```

- **본인인증을 해야 모든 기능을 쓴다.** 인터뷰도 인증 뒤다
- 엔진 계획의 `Participant`(본인인증 전 임시 참여자)는 두지 않고 `User` 하나로 간다
- 미성년자가 인터뷰 전에 걸러진다. 성인 서비스라 맞는 순서다
- 기본 정보·사진을 이 흐름의 어디에 둘지는 진입 흐름을 설계할 때 정한다(`BACKLOG.md` 8절). 사진은 편지(2단계)에 필요하다
- 대가: 인증 단계에서 이탈이 생긴다. **설치 → 인증 완료 전환율**을 지표로 본다(11장)

# 13. 열린 질문 (조각별 고도화 때)

1. **인터뷰** — 장별 문항과 깊이, 턴 수 조절, 한 장이 끝나는 기준
2. **매일 대화** — 소재를 고르는 규칙, 사용자가 먼저 거는 대화에서 상담의 범위
3. **위기 신호** — 감지 방식(규칙 + AI), 대화방에서의 안내 화면
4. **서고** — 장 길이 예산, 점검 주기, 갈피 빼기의 범위(같은 원문에서 나온 다른 문장도 함께 정리되는지, 빼기 전에 무엇을 보여줄지), 원문 보관 기간 재검토(출시 전 법률 자문)
5. **리포트** — 갱신 가격과 주기, 갱신을 열 수 있는 시점(서고가 얼마나 자라야 하나)
6. **조건 증빙** — 항목과 방식(편지 D1 설계 때)
7. **공용 위키** — 최소 인원, 경향을 뽑는 주기, 상담 친구가 나오는 시점
