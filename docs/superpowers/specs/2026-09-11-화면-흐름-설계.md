# 0. 이 문서의 목적

컨셉 문서는 "무엇을 왜"까지 정했고, 이 문서는 **"화면에서 실제로 무슨 일이 일어나는가"**를 정한다.

**백엔드보다 이걸 먼저 하는 이유:** 우리 컨셉에는 아직 정의되지 않은 UX가 많다(거절 UX, 매일 대화, 대기 화면, 리포트 표현). 화면을 짜는 과정에서 발견되는 것들이 있고, 그게 백엔드 명세를 바꾼다. 6장에 실제로 발견된 것들을 모았다.

# 0.5 플랫폼과 내비게이션 구조 (2026-09-17 결정)

## 플랫폼: React Native (Expo)

`apps/mobile` 에 만든다. 원래 아키텍처 스펙대로다.

**웹이 아니라 RN 인 이유:** 우리 핵심 경험이 *"좋은 상대가 나타나면 알림"* 인데 **웹 푸시는 iOS 제약이 크다.** `expo-notifications` 가 이미 들어가 있다.

**대가:** 컨셉 문서 2.8 의 CAC 계산에서 잡은 **설치→가입 50% 손실이 그대로 발생한다.** 다만 `react-native-web` 이 이미 의존성에 있어 **나중 웹 확장은 같은 코드로 간다.** 랜딩 페이지만 별도 웹으로 둔다.

## 내비게이션: 탭이 아니라 하나의 대화창 ⭐

**기존 4탭 구조(홈/관심/대화/마이)는 폐기한다.** 하드룰 1(진열 금지)을 지키면 탭이 설 자리가 없다. 탭을 두는 것 자체가 "둘러볼 곳이 여러 개"라는 감각을 만든다.

> **앱의 루트는 주선자와의 대화창이다. 거기서 모든 것이 일어난다.**

| 일어나는 일 | 어디서 |
|---|---|
| AI 인터뷰 | 주선자 대화창 |
| 매일 대화 | 주선자 대화창 |
| **소개 받기** | 주선자가 대화 중 카드를 건넨다 — *"소개드릴 분이 있어요"* |
| 넘긴 이유 말하기 | 주선자가 바로 묻는다 |
| 만난 뒤 피드백 | 주선자가 며칠 뒤 묻는다 |
| 대기 상태·카운터 | 주선자 대화창 상단 |

**별도 화면은 둘뿐이다** — 연결된 사람과의 대화, 그리고 나(리포트·연결권·설정).

**왜 이게 맞나**
- 주선자 은유와 정확히 맞는다. 실제 주선자와의 관계도 하나의 대화다
- **진열이 구조적으로 불가능해진다.** 목록을 놓을 자리가 없다
- 초기 사용자는 연결된 대화가 0~1개다. 탭을 채울 것이 애초에 없다

**구조**

```
app/
  (main)/
    index.tsx          주선자 대화창 (루트)
    chats/index.tsx    연결된 사람 목록 — 1개 이상일 때만 진입점 노출
    chats/[id].tsx     연결된 사람과의 대화
    me/index.tsx       나 (리포트·연결권·설정)
```

## 기존 `apps/mobile` 정리 범위

| 폐기 | 재사용 |
|---|---|
| `(tabs)/` 전체 — 4탭 구조 | `(auth)/a01-splash.tsx`, `(auth)/a03-login.tsx` |
| `(tabs)/interests.tsx` — 관심 목록은 진열 | `lib/api.ts`, `lib/supabase.ts`, `lib/auth-storage.ts` |
| `recommendations/[id].tsx` — 추천 카드 | `report.tsx` (신고) |
| `(onboarding)/b04~b07` — 폐기된 온보딩 문항 | `my/j03-verifications.tsx`, `my/j07-withdraw.tsx` |
| `profile-edit.tsx` — 조건표형 프로필 | |

# 1. 전체 화면 지도

```
[A 진입 — 별도 스택]
A1 랜딩(웹)  →  A2 동의 3종  →  A3 기본 정보
                                     │
                                     ▼
┌──────────── 주선자 대화창 (루트, 모든 것이 여기서) ────────────┐
│                                                              │
│  B 인터뷰        C 대기           D 소개                      │
│  B1 시작 안내    C1 대기 상태     D1 소개 카드 ⭐             │
│  B2 대화 ⭐      C2 매일 대화 ⭐  D2 넘긴 이유 ⭐             │
│  B3 이어서 하기  C3 리포트 입구   F2 만난 뒤 ⭐               │
│  B4 완주                                                     │
└──────────────────────────────────────────────────────────────┘
                     │                        │
                     ▼                        ▼
[E 연결된 대화 — 별도]        [G 나 — 별도]
E1 연결 안내                  G1 내 리포트   G2 연결권
E2 대화                       G3 내 정보     G4 차단·신고
E3 통화                       G5 결정 설명 요청
F1 만남 약속
```

**A 진입만 별도 스택이고, B·C·D·F2 는 전부 주선자 대화창 안에서 일어난다.**

⭐ = 이 제품의 성패가 걸린 화면

# 2. A 진입

## A1 랜딩

**목적:** "진열되지 않는 소개팅"이 무엇인지 10초 안에 전달하고 시작시킨다.

**전달할 것 (순서대로)**
1. 한 문장 — *"당신을 아무에게도 보여주지 않는 소개팅"*
2. 무엇이 없는지 — **둘러보기 없음, 검색 없음, 내 프로필이 떠다니지 않음**
3. 무엇이 있는지 — AI가 20분 대화로 나를 이해하고, 맞는 사람이 나타날 때만 알림
4. 지금 상태 — *"OO명이 함께 기다리는 중"*

**하드룰 체크:** "검증된 사람만" 같은 안전 단정 금지(CLAUDE.md §9.1). "100% 안전" 금지.

**측정:** 방문 → A2 진입 전환율

## A2 동의 (3종 분리)

**목적:** 법적 요구를 충족하되 이탈을 최소화한다.

| 동의 | 필수 | 없으면 |
|---|---|---|
| 개인정보 수집·이용 | 필수 | 진행 불가 |
| **민감정보 처리** | 선택 | 종교까지 마스킹되어 매칭 정확도가 떨어짐 |
| **국외이전 (AI 처리)** | 필수 | AI 인터뷰 불가 |

**설계 원칙**
- 세 개를 한 화면에 두되 **체크박스를 분리**한다. 묶음 동의 금지
- 각 항목에 **왜 필요한지 한 줄**을 붙인다. 법률 문구만 두지 않는다
- 민감정보 동의는 *"종교나 건강 얘기가 나올 수 있어서"*라고 솔직하게 설명한다

**위험:** 여기가 최대 이탈 지점이다. 특히 "국외이전"이라는 단어가 겁을 준다. **카피 설계가 중요하다.**

## A3 기본 정보

성별, 출생연도, 생활권, 직군(선택). **이게 전부다.**

**하드룰 체크:** 학벌·연봉·주거는 **여기서 묻지 않는다.** 갈피가 인터뷰 중에 묻고, 본인이 허락한 항목만 소개 편지에 담긴다(2026-10 변경, 컨셉 5.8).

# 3. B 인터뷰 — 제품의 심장

## B1 시작 안내

**목적:** 20분이라는 시간을 납득시킨다.

- *"20분쯤 걸립니다. 중간에 멈춰도 이어서 할 수 있어요."*
- 끝나면 받는 것을 미리 보여준다 — *"당신을 이렇게 이해했습니다"* 리포트 예시 한 문단

## B2 대화 화면 ⭐

**구성**
- 상단: 나가기 버튼 + 진행 정도(숫자가 아니라 흐릿한 막대)
- 본문: 말풍선. AI 질문 → 내 답변
- 하단: 입력창. **전송 버튼 외에 아무것도 없다**

**설계 결정**
- **진행률을 숫자로 보여주지 않는다.** "12/25"는 설문 느낌을 준다. 흐릿한 막대만
- **AI 응답은 스트리밍**한다. 기다림이 대화처럼 느껴져야 한다
- **건너뛰기 버튼을 둔다.** 답하기 싫은 질문이 반드시 나온다. 안 두면 이탈한다
- 한 번에 하나만 묻는다(프롬프트에 이미 반영)

**하드룰 체크:** 읽음 확인·타이핑 표시 같은 압박 장치 금지(하드룰 6). AI 대화에서도 마찬가지.

**측정:** 완주율(목표 60%), 평균 턴 수, 이탈 지점 분포

## B3 이어서 하기

**20분을 한 번에 하는 사람은 소수다.** 중간 이탈은 실패가 아니라 기본값으로 가정한다.

- 자동 저장. 다시 들어오면 *"이어서 하시겠어요?"*
- **리마인드는 최대 1회, 24시간 뒤.** 그 이상은 압박이다

## B4 완주

- 완주 조건: 최소 12턴
- 완주 즉시 리포트 생성(10~20초). **이 대기 시간을 숨기지 말고 "읽고 있습니다"로 보여준다**

# 4. C 대기 — 죽음의 계곡

컨셉 문서 11장에서 지적한 구간. **여기서 대부분이 떠난다.**

## C1 대기 상태 (주선자 대화창 상단)

별도 홈 화면이 아니라 **주선자 대화창의 상단 띠**다.

**보여줄 것**
- **투명한 카운터** — *"지금 OO명. N명이 되면 소개를 시작합니다"*
- 내 리포트로 가는 입구

**보여주지 않을 것**
- 다른 사람의 프로필, 수, 사진 — **어떤 형태의 목록도 없다**(하드룰 1)

## C2 매일 대화 ⭐

**목적:** 빈 기간을 채우고, 동시에 AI의 이해를 깊게 한다.

- 하루 한 개의 짧은 질문. 2~3턴이면 끝
- 답하면 **리포트가 조금씩 자라는 게 보인다**
- **안 해도 불이익이 없다.** 연속 기록·스트릭 같은 장치를 두지 않는다

**Luna 단가로 월 45원.** 6개월 전에는 불가능했던 기능이다.

## C3 내 리포트

- 완주 시점의 리포트
- 매일 대화가 쌓이면 **갱신 가능** 표시. 갱신은 유료(단건)

# 5. D 소개 — 진열하지 않고 소개하기

## D1 소개 카드 ⭐

**푸시 알림 → 주선자 대화창.** 별도 화면으로 가지 않는다.

- **좋은 상대가 있을 때만.** 정기 배급 없음(하드룰 3)
- 알림 문구에 상대 정보를 넣지 않는다. *"소개드릴 분이 있습니다"*
- 앱을 열면 주선자가 말을 건다 — *"소개드릴 분이 있어요"* 하고 **대화 흐름 안에 카드가 놓인다**

**한 사람만 보인다. 목록이 아니다.**

**구성**
1. 사진 (처음부터 보여준다 — 주선자는 사진을 보낸다)
2. 실용 정보 — 생활권, 나이, 흡연, 결혼 의향
3. 신뢰 배지 — 신원 확인, **재직 확인**
4. 본인이 허락한 조건 정보 — 학교·연봉·회사·주거 중 허락한 항목만 (2026-10 변경. 인증 여부와 표시 방식은 미정)
5. **"왜 이 분인가"** — AI가 쓴 한 문단
6. 수락 / 넘기기

**보여주지 않는 것:** 상대의 인터뷰 원문, 넘긴 이유, 본인이 거절한 조건 정보(하드룰 2, 8)

**설계 결정:** 넘기기 전에 **되돌리기를 허용하지 않는다.** 되돌리기가 있으면 "일단 넘기고 보자"가 되고, 그건 스와이프다.

## D2 넘긴 이유 말하기 ⭐

**우리 학습 데이터의 전부가 여기서 나온다.**

- 넘기면 **같은 대화창에서** 주선자가 바로 묻는다 — *"어떤 점이 아니었나요?"*. 화면 전환이 없다
- **자유 입력이 기본.** 선택지 버튼은 성의 없는 답을 만든다
- **건너뛸 수 있다.** 강제하면 거짓말이 쌓인다
- 화면에 명시한다 — **"이 내용은 상대에게 전달되지 않습니다"**

**측정:** 이유 입력률. 이게 낮으면 컨셉의 학습 루프가 작동하지 않는다.

# 6. E 연결 / F 만남

## E1 연결 안내 (크레딧 차감 지점)

- 양쪽이 수락하면 대화가 열린다
- **차감은 대화가 성립한 뒤**(양쪽 2~3턴). 이 화면에서는 안내만
- 크레딧이 없으면 구매 화면. **여기가 결제 이탈 지점이다**

## E2 대화

- 기한 없음. 붙잡지도 내보내지도 않는다(컨셉 5.6)
- 읽음 확인·온라인 상태 없음
- **그만하기 버튼을 상시 노출한다.** 거절이 잠수보다 쉬워야 한다(컨셉 6.5)
- 연락처 교환을 **권하지 않는다.** 기능은 있되 유도 카피 없음(하드룰 5)

## E3 통화

인앱 음성통화. 만남 약속·당일 연락용. 실번호를 주지 않아도 되게 하는 장치.

## F2 만난 뒤 ⭐

- 만남 며칠 뒤 한 번 묻는다 — *"어떠셨어요?"*
- **과금과 무관하다.** 돈이 걸리면 숨긴다(컨셉 6.4)
- 평가가 아니라 **내 이야기로 받는다** — *"그 사람이 별로였다"*가 아니라 *"나는 이런 대화가 편했다"*
- 상대가 잠수했다면 여기서 드러난다

# 8. 설계하며 발견한 것

화면을 짜면서 나온 것들이다. **컨셉 문서에 없던 내용이다.**

## 8.1 새로 필요해진 것

| 발견 | 왜 |
|---|---|
| **인터뷰 중간 저장 + 이어하기** | 20분을 한 번에 하는 사람은 소수다. 중간 이탈을 실패가 아니라 기본값으로 봐야 한다 |
| **인터뷰 중 건너뛰기 버튼** | 답하기 싫은 질문이 반드시 나온다. 없으면 그 지점에서 이탈한다 |
| **완주 전 "맛보기" 한 줄** | 5턴쯤에서 *"지금까지 이렇게 보입니다"*를 주면 완주 동기가 생긴다. 완주율이 목표치를 못 넘기면 첫 번째로 시도할 장치 |
| **리포트 생성 대기 화면** | 10~20초가 걸린다. 숨기지 말고 "읽고 있습니다"로 보여준다 |
| **그만하기 버튼 상시 노출** | 컨셉 6.5의 "쉬운 거절"이 화면에서는 이 형태다 |
| **G5 결정 설명 요청 화면** | 법적 요구인데 컨셉 문서에는 "창구를 둔다"고만 적혀 있었다. 화면이 필요하다 |
| **앱 전체를 하나의 대화창으로** (0.5 참조) | 하드룰 1 을 지키면 탭이 설 자리가 없다. 탭을 두는 것 자체가 "둘러볼 곳이 여러 개"라는 감각을 만든다. 소개·거절·피드백이 전부 주선자와의 대화 안에서 일어나면 **진열이 구조적으로 불가능해진다** |

## 8.2 설계 결정으로 바뀐 것

- **진행률을 숫자로 표시하지 않는다.** "12/25"는 설문 느낌을 준다. 우리는 대화를 판다
- **넘기기 되돌리기를 허용하지 않는다.** 되돌리기가 있으면 "일단 넘기고 보자"가 되고, 그건 스와이프의 다른 이름이다
- **거절 이유는 자유 입력이 기본.** 선택지 버튼은 빠르지만 성의 없는 데이터를 만든다. 우리 차별점이 "비트가 아니라 언어"인데 버튼은 비트다
- **매일 대화에 스트릭·연속 기록을 두지 않는다.** 압박 장치이고 하드룰 6에 걸린다
- **소개를 보러 가는 곳으로 만들지 않는다.** 별도 화면은 "보러 가는 곳"이 되고, 그건 진열에 가까워진다. (2026-10-10 갱신: 편지 페이지는 두되, 갈피가 건네는 사건으로만 열린다 — 편지는 갈피 대화방의 편지 카드와 친구 탭의 중요한 일 카드로 오고, 소개 탭이나 편지함은 없다)

## 8.3 미해결로 남은 것

1. **A2 동의 화면의 이탈률.** "국외이전"이라는 단어가 겁을 준다. 카피를 어떻게 쓸 것인가
2. **E1 결제 이탈.** 서로 수락했는데 크레딧이 없는 순간. 가장 아까운 이탈이다
3. **상대가 나를 넘겼을 때 알리지 않는데**, 그러면 사용자는 무엇을 보고 기다리나
4. **인터뷰 맛보기를 주면 완주 전에 만족하고 떠날 수도 있다.** 양날이다
5. **카운터 숫자를 조작 없이 정직하게 보여줄 때**, 초기에 숫자가 너무 작으면 오히려 이탈시킨다
