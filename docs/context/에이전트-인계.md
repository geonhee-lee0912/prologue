# Claude Code·Codex 교대 개발

갱신: 2026-10-31. 이 저장소의 코드는 TypeScript·pnpm 프로젝트이며 작성한 도구에 종속되지 않는다. 기존 코드를 변환하거나 프로젝트를 다시 만들 필요 없이 두 도구로 이어서 개발한다.

## 개발 도구와 서비스 AI의 구분

루트 `AGENTS.md`와 `CLAUDE.md`는 코드를 만드는 개발 도구가 읽는 작업 지침이다. 이 저장소의 `AGENTS.md`는 기존 `CLAUDE.md`의 개발 지침을 옮겨 만든 파일이다. 제품 안의 갈피 AI나 개별 서비스 에이전트 설정을 뜻하지 않는다.

갈피의 실제 LLM 메시지는 `apps/api/src/galpi/prompt/system-prompt.ts`의 상수와 `reply-prompt.ts`, 서고 수집·리포트의 prompt 모듈에서 구성한다. 현재 서비스 코드가 루트 `AGENTS.md`·`CLAUDE.md`를 프롬프트로 읽는 경로는 없다. 작업 지침을 수정하는 것과 제품의 AI 행동을 바꾸는 것은 구분한다.

## 공통으로 읽는 기준

- **지침:** 루트 `AGENTS.md`가 공통 원본이다. `CLAUDE.md`는 `@AGENTS.md` 한 줄로 이를 불러온다. 규칙을 두 파일에 복제하지 않는다.
- **현재 작업:** 사용자 요청과 `BACKLOG.md`, 해당 영역의 설계·결정 기록을 읽는다. 공통 플랫폼 작업·패키지 연결은 프롤로그의 우선순위나 선행 조건이 아니다.
- **코드·검증:** Git 커밋·PR과 `package.json`·`pnpm-lock.yaml`을 기준으로 삼는다. 실행 명령은 `README.md`를 따른다. shared를 바꿨으면 다른 앱을 검증하기 전에 빌드한다.
- **변경 이력:** 긴 과거 기록은 `작업-지침-변경-이력.md`에 둔다. Codex의 기본 프로젝트 지침 한도는 합산 32KiB이므로 `AGENTS.md`를 짧게 유지하고 하위 지침 추가 시에도 크기를 확인한다.

Claude Code의 `@파일` import는 공식 지원 방식이다. 별도 native AGENTS 지원 여부에 관계없이 이 저장소에서는 `CLAUDE.md`를 통해 공통 지침을 불러올 수 있다. 개인·회사 관리 설정으로 프로젝트 지침을 제외한 세션에서는 실제 로딩 상태를 확인한다.

## 교대할 때

1. **현재 상태 확인:** 브랜치·HEAD·PR과 `git status`를 확인한다. 같은 브랜치·파일을 두 도구가 동시에 수정하지 않는다.
2. **작업 보존:** 진행 중인 변경도 설명 가능한 단위로 커밋하고 필요하면 draft PR로 게시한다. 미완료 코드를 완성된 것으로 표시하지 않는다. 다른 환경의 미커밋 변경은 전달되지 않으므로 PR·커밋을 기준으로 넘긴다. 푸시 승인 범위는 `AGENTS.md`를 따른다.
3. **인계 내용 기록:** 해당 BACKLOG 항목이나 PR 본문에 목표, 완료/남은 일, 다음 단계, 실행한 검사와 결과, 필요한 승인·설정 이름을 적는다. 비밀값은 적지 않는다.
4. **이어서 진행:** 다음 도구는 게시된 커밋·PR과 인계 내용을 읽고 이어간다. 열린 PR을 이어받으면 그 브랜치를 순차적으로 사용한다. 별도 작업은 최신 기준에서 새 브랜치를 쓴다. 작업을 처음부터 다시 만들거나 상대의 커밋을 덮어쓰지 않는다.
5. **검증·승인:** 변경에 맞는 검사를 수행하고 PR의 결과를 갱신한다. 병합은 운영자가 한다. 자동 병합·DB 적용·운영 콘솔 변경의 승인 범위는 교대해도 바뀌지 않는다.

인계는 특정 도구의 사용량 한도가 끝났을 때뿐 아니라 운영자가 도구를 바꾸고 싶을 때도 가능하다. 프롤로그의 주 담당을 Claude 또는 Codex로 고정하지 않는다.

## 로딩 확인과 근거

지침을 바꾼 뒤에는 새 세션을 시작해 최신 커밋의 지침을 읽는다. Claude Code에서는 `/context`의 Memory files에서 `CLAUDE.md` 로딩을 확인하고, 두 도구 모두 현재 규칙과 작업 상태를 요약하게 해 확인할 수 있다. 다른 도구의 채팅 내용을 알고 있다고 가정하지 않는다.
