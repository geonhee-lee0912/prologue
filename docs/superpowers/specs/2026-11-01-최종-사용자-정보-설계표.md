# 최종 사용자 정보 설계표

상태: 전체 구조 검토용 초안. 운영자가 승인한 원칙과 아래 제안을 구분한다. 구현·인증 제공자 연결·법적 검토 완료를 뜻하지 않는다.

제품의 기본은 소개팅 앱이며 깊이 있는 주선으로 결정사의 대안이 될 수 있도록 한다. [확정 컨셉](../../decisions/2026-11-01-소개팅앱과-깊이있는-주선.md)을 따른다. [결정사 공식 자료 조사와 소개 전 필수 정보 추천안](../../research/2026-11-01-결정사-정보수집과-소개준비.md)은 검토 근거이며, 필수 후보는 하나씩 운영자가 결정한다.

## 목표와 확정 원칙

- 설계표 전반에서 갈피가 덧묻는 질문은 [갈피 엔진 7장](2026-10-11-갈피-AI-엔진-design.md)의 ‘앞서 나눈 답을 더 알아가는 대화’ 유형에 묶는다. 갈피가 먼저 전에 나눈 이야기를 꺼내고, 답의 배경을 이해해 다음 소개에 활용한다. 사용자에게 확인한 선호를 기준으로 삼는다.

- 2026-11-06 재검토 8번. 자녀가 있는 상대와의 만남에 대한 생각은 갈피와 대화로 알아간다. 사용자가 원하지 않는다고 확인한 조건에 해당하면 그 두 사람 사이의 소개를 제외한다. ‘아직 모르겠어요’ 또는 미응답이면 해당 소개 전에 본인 의사를 확인하고 수용 의사가 확인된 경우에만 진행한다. 동거·직접 양육에 따라 답이 달라질 때만 필요한 범위를 확인한다. 본인의 혼인 이력·자녀 유무와 상대에게 바라는 조건은 구분하고, 확인된 기준은 개인별 소개에만 적용한다.

- 재검토 8번 자녀 정보 확정: 혼인 경험이 있는 사람에게 자녀 여부를 묻고, 그 외에는 본인이 직접 추가할 수 있게 한다. 자녀가 있으면 함께 사는지와 직접 양육하는지를 각각 확인한다. 소개 준비 때 간단히 직접 선택하며 이미 대화에서 말한 내용은 본인 확인만 받는다. 자녀 유무·동거·직접 양육 여부는 선정된 소개 상대가 수락 전에 알 수 있도록 소개 편지에 공개한다. 질문을 생략한 상태를 ‘자녀 없음’으로 간주하지 않는다. 자녀의 이름·사진·학교 등 식별 정보는 받지 않는다. 이 결정은 본인 답변의 수집·공개 범위이며 증빙 인증 완료를 뜻하지 않는다. 다음은 자녀가 있는 상대에 대한 생각을 확인하는 방식이다.

- 재검토 7번 상대의 혼인 경험에 대한 생각 확정: 갈피와 대화로 알아가고 소개 전에 정리한 내용을 본인에게 확인한다. 이혼 경험과 사별 경험에 대한 생각을 무조건 하나로 묶지 않고, 본인의 혼인 경험으로 상대에 대한 수용 의사를 추정하지 않는다. 자녀가 있는 상대에 대한 생각은 별도로 다룬다. 확인하지 않은 대화 해석을 소개 기준으로 확정하지 않으며 중요도·유연성의 세부 적용은 후속 설계로 남긴다. 다음은 8번 자녀 정보의 수집·공개 방식이다.

- 재검토 7번 혼인 경험 공개 확정: 앞서 받은 혼인 상태를 재사용하며 중복 질문하지 않는다. ‘결혼 경험 없음 / 이혼 경험 있음 / 사별 경험 있음’을 소개 편지에 간결하게 표시하고 상대가 수락 전에 알 수 있게 한다. 소개 전 본인에게 실제 표시 내용을 보여준다. 공개는 선정된 소개 상대에게 전달하는 범위이며 검색·목록·불특정 다수에게 노출하는 프로필을 뜻하지 않는다. 이혼 사유·전 배우자 정보·대화 원문은 공개하지 않는다. 본인 답변과 선택 증빙의 확인 상태는 구분한다. 상대의 혼인 경험에 대한 생각은 위 결정에 따라 대화 후 소개 전에 본인이 확인한다.

- 재검토 6번 혼인 상태 증빙 확정: 본인 답변으로 소개 준비를 진행하고 증빙 인증은 선택으로 둔다. 첫 소개의 필수 관문으로 삼지 않는다. 인증한 경우에만 실제 확인 범위·확인 시점을 표시하며 미인증 답변을 증빙된 사실로 표시하지 않는다. 미인증을 이유로 불이익을 주거나 의심을 유도하는 표현을 피한다. 자세하고 확인된 정보를 점진적으로 쌓는 목표는 유지한다. 증빙 수단·제출 절차·비용·갱신·보관 방식과 실제 연동은 미확인 또는 미정이며 이번 결정은 외부 서비스 도입·유료 호출·DB 변경 승인이 아니다.

- 재검토 6번 혼인 상태 확인 방식 확정: 소개 준비 때 ‘결혼한 적 없어요 / 이혼했어요 / 배우자와 사별했어요 / 현재 혼인 중이에요’를 직접 선택한다. 현재 혼인 중에는 별거·이혼 절차 진행을 포함하며 혼인 종료 후 새 소개를 진행한다. 나머지는 소개 준비를 계속하고 필요한 후속 정보를 확인한다. 현재 상태와 혼인 경험을 함께 받아 중복 질문을 줄이며, 이혼 사유·전 배우자 이야기는 이 단계에서 묻지 않는다. 본인 답변과 증빙으로 확인한 상태를 구분한다. 증빙은 선택이며 수단·갱신 방식은 아직 결정하지 않았다.

- 재검토 6번 중 연애 상태 확정: 연애 상태는 별도 질문·체크박스로 받지 않고 소개 이용 기준으로 안내한다. 현재 배우자나 교제 중인 연인이 없는 사람에게 새 소개를 진행한다는 기준은 유지한다. 질문 생략을 ‘연인 없음’이라는 확인된 사실로 저장하거나 인증 표시하지 않는다. 혼인 상태는 아래 네 가지 선택지로 직접 확인하며 증빙은 선택이다. 기존 교제 상태 직접 확인 결정은 이 결정으로 대체한다.

- 재검토 5번 결혼 의향·시기 확정: 갈피와 대화로 알아가되 소개 전에 본인이 의향을 명확히 확인한다. ‘생각이 있어요 / 아직 모르겠어요 / 생각이 없어요’를 기본으로 맥락을 보완한다. 결혼 생각이 있는 사람에게만 생각하는 시기를 묻고 ‘정해두지 않았어요’를 허용한다. 본인이 확인한 의향·시기의 짧은 요약을 상대에게 공개한다. 진지한 연애 의향으로 결혼 의향을 추정하지 않고, 결혼 의향 없음·미정과 시기 미정을 구분한다. 다음 논의는 6번 현재 혼인·연애 상태다.

- 재검토 4번 원하는 관계 확정: 갈피와 자연스럽게 대화하며 관계에 바라는 점·시작하는 속도·진지한 관계로 발전할 마음을 알아간다. 소개 준비 때 갈피가 정리한 요약을 본인이 확인·수정하고, 확인한 짧은 요약만 소개 편지에 담는다. 원문 대화나 확인하지 않은 AI 해석을 공개하지 않는다. 원하는 관계와 결혼 의향은 분리하며 결혼 의향·시기는 다음 5번에서 논의한다. 구체적인 질문 문구와 화면은 상세 설계 대상이다.

- 재검토 3번 중 상대 연령 범위 확정: 소개 준비 때 원하는 최소·최대 만 나이를 확인하고 ‘나이는 크게 상관없어요’도 선택할 수 있게 한다. 갈피와의 대화에서 이미 말한 내용은 범위로 정리해 본인 확인을 받으며 재입력을 요구하지 않는다. 희망 연령 범위 자체는 상대에게 공개하지 않는다. 범위 밖 상대의 소개 허용 여부는 선호 중요도·유연성 상세 설계에서 별도로 정하며, 이번 결정으로 범위를 임의 확대하지 않는다. 나이 선호 없음은 성인 인증 원칙의 예외가 아니다. 다음 논의는 4번 원하는 관계다.

- 재검토 2번 중 이름 확정: 상대에게 공개하는 이름은 닉네임이다. 갈피가 부르는 호칭은 닉네임을 기본으로 하되 사용자가 실명이나 편한 호칭을 직접 정하고 언제든 바꿀 수 있다. 인증 원본의 실명을 자동으로 가져오지 않으며 갈피용 호칭은 소개 편지·상대 대화에 자동 공개하지 않는다. 직접 입력한 실명도 개인정보 보호 대상이고 AI 전송 시 식별자 가명처리 원칙을 유지한다. 저장·호칭 치환의 구체적 구현은 미정이다.
- 재검토 2번 중 나이 확정: 인증으로 확인한 만 나이를 사용하고 중복 입력을 요구하지 않는다. 상대에게는 나이만 공개하며 생년월일은 공개하지 않는다. 인증 원본 생년월일의 검증 후 폐기 원칙을 유지한다. 나이 갱신에 필요한 최소 정보와 처리 방식, 인증 제공자가 지원하는 범위는 구현 전 별도로 확인한다. 이번 결정은 원본 생년월일 저장 승인이나 실제 연동 완료를 뜻하지 않는다.
- 재검토 2번 중 성별 확정: 성별을 확인할 수 있는 본인인증 수단을 선택하고 인증 결과의 성별을 사용하며 별도로 다시 입력받지 않는다. 원하는 상대 성별은 본인 성별과 별도 설정으로 관리하며 아래 3번 결정에 따른다. 인증 제공자 선정·실제 연동 검증은 미완료이며 인증 결과가 누락된 경우의 처리는 상세 설계에서 정한다.
- 재검토 3번 중 상대 성별 확정: 가입 때 별도 필수 질문을 하지 않고 이성을 기본 소개 대상으로 설정한다. 소개 준비 요약에서 ‘소개받을 상대: 여성/남성 · 변경’처럼 보여주고 본인이 확인·변경할 수 있게 한다. 시스템 기본값과 본인이 확인한 선택을 구분해 기록한다. 기본값을 사용자의 확정된 선호로 간주하지 않는다. 변경 가능한 선택지와 실제 지원 소개 범위는 함께 상세 설계하며 모든 소개 조합의 구현 완료를 뜻하지 않는다. 상대에게 선호 설정 원본을 공개하지 않는다. 다음 논의는 원하는 상대 연령 범위다.
- 갈피는 나를 알아가며 소개팅해주는 친구로 경험하도록 한다. AI임을 알리는 원칙과 깊은 대화의 비공개 원칙은 유지한다. 가입 시점의 상세 화면 배치는 아직 재확정하지 않았다.

- 2026-11-02 전체 추천안 재검토: 기존 결정도 이력으로 유지하면서 수집 방식·시점·필수 여부·확인·공개를 항목별로 다시 의논한다. 전체 추천표 제시는 일괄 승인이 아니다.
- 재검토 1번 확정: 본인·성인 인증을 마친 뒤 갈피와 대화를 시작한다. 기존 인증 선행 원칙을 유지한다. 실제 인증 제공자 연결과 동작 검증 완료를 뜻하지 않으며, 다음 논의는 2번 이름·나이·성별이다.

- 종교는 본인의 종교 유무·종류, 일상에서 중요한 정도, 상대에게 같은 종교나 종교 활동 동참을 바라는지를 포함한다. 별도 동의한 사람이 선택적으로 제공한다. 미입력을 무교로 해석하지 않으며 갈피가 먼저 캐묻거나 추정하지 않는다. 공개·추천 적용·구체적인 수집 화면은 이후 결정한다.

- 본인 이름·나이·성별, 원하는 상대 성별·연령 범위를 정보 목록에 포함한다. 이름·호칭의 구분과 나이의 수집·공개, 성별의 인증 결과 활용 및 상대 성별·연령 범위의 설정·확인은 위 재검토 결정에 따른다. 연령 범위의 유연성과 상세 화면은 미정이다. 수집 범위 확정만으로 서비스의 모든 소개 조합이 구현·지원됐다는 뜻은 아니다.

- 기본 프로필·소개 대상 범위·외형 정보·종교를 필요한 정보 영역에 포함하기로 승인됐다. 세부 항목·필수 여부·공개·수집 방식은 일괄 확정한 것이 아니다. 종교는 기존 별도 동의 및 갈피의 직접 질문 제한을 유지한다.
- 외형 정보 후보에는 사진·키·체형·평소 스타일을 포함한다. 외형을 추천에 반영하는 방식은 중요한 별도 상세 설계 과제로, 상대 선호의 중요도·유연성과 함께 다룬다. 체형 선택지·추정 방법·필터·가중치를 지금 확정하지 않는다.

- 가까운 미래의 생활 변화는 갈피와의 대화로 알아간다. 이사·유학·장기 체류·일이나 학업에 따른 시간 변화가 만남에 영향을 줄 때, 소개 준비에서 본인이 확인한 구체적인 계획만 만남 가능 지역이나 시간에 반영한다. ‘언젠가 이사하고 싶다’는 희망으로 기록하고, ‘다음 달 부산으로 이사한다’는 본인 확인 후 해당 시점의 만남 가능 지역에 반영한다. 변화 계획 자체를 소개 편지에 공개할 범위는 별도로 정한다.

- 여가·휴식 방식은 취미·관심사의 세부 정보로 묶는다. 집에서 쉬기와 외부 활동의 선호, 계획·즉흥적인 시간 사용, 함께하는 여가에서 원하는 시간을 이해할 후보로 포함한다. 이 세부 정보의 수집 방식·필수 여부·질문·소개 활용은 이후 결정한다. 기존 취미의 가벼운 명시적 입력 합의는 유지한다.

- 애정·관심을 표현하는 방식과 받고 싶은 방식을 구분해 정보 후보에 포함한다. 본인이 표현하는 방식으로 원하는 상대의 표현을 추정하지 않는다. 수집 방식·필수 여부·구체적 질문·소개 활용은 이후 결정하며 고정 유형으로 분류하지 않는다.

- 의견이 다르거나 서운할 때 대화하는 방식을 정보 후보에 포함한다. 이야기할 시점·생각할 시간의 필요, 서운함을 표현하는 방식, 편안하게 대화할 수 있는 상대의 반응을 이해한다. 수집 방식·필수 여부·구체적 질문·소개 적용은 미정이다. 성격의 우열이나 고정 유형으로 단정하지 않는다.

- 편안하게 느끼는 관계 방식도 알아갈 정보에 포함한다. 연락·만남의 희망 빈도, 혼자 보내는 시간과 함께하는 시간의 균형을 다룬다. 실제 만남 가능한 시간과 구분하며 수집 방식·필수 여부·구체적 질문·소개 적용은 미정이다.

- 후속 진행 순서: 먼저 필요한 정보 전체와 목적을 정하고, 명시적 입력·갈피 대화·병행 중 수집 방식을 나눈 뒤 가입·알아가기·소개 준비에 배치한다. 기존 합의는 유지하며 전체 검토에서 조정할 필요가 있는 부분만 다시 의논한다.
- 자신의 강점·자랑스럽게 여기는 점·꾸준히 해온 일·의미 있는 경험을 정보 후보에 포함한다. 자격처럼 확인 가능한 이력과 주관적인 강점을 구분한다. 별도 입력란·필수 여부·수집 방식은 아직 결정하지 않았다.

- 취미·관심사는 부담 적은 명시적 입력으로 여러 개 선택하고, 짧은 설명은 원하는 항목에만 추가한다. 등록·공개는 선택이다. 구체적으로 즐기는 방식과 맥락은 갈피 대화에서 알아간다. 명시적 입력을 없애거나 대화로만 수집하는 안은 채택하지 않는다. 설명 작성을 강제하거나 대화 내용을 다시 작성하게 하지 않는다.

- 주거는 현재 생활 형태와 주거 보유·계약 형태를 구분하고, 두 항목 각각 선택 등록·선택 공개한다. 정확한 주소는 받지 않는다. 가족 소유 주택 거주를 본인 소유로 간주하지 않는다. 세부 선택지·명의 구분·증빙은 미정이다.

- 소득은 현재 계약 연봉과 특정 연도의 실제 연간 소득을 구분해 선택 등록할 수 있게 한다. 둘 다 일괄 필수로 받지 않는다. 기존 선택 공개·구간 표시 방향을 유지하되 기준 기간·세전/세후·소득 포함 범위·부업 합산·증빙은 상세 설계에서 결정한다.

- 학력은 학교명·전공·학위·재학/졸업 등 상태를 선택적으로 등록하며 각 항목의 공개 여부를 따로 선택한다. 등록이나 증빙으로 자동 공개하지 않는다. 세부 선택지·증빙 방식은 별도 결정한다.

- 하는 일의 큰 범주와 현재 활동 상태는 소개 전에 확인한다. 회사명·직급·소득은 선택으로 둔다. ‘다른 일·활동 추가’로 여러 활동과 짧은 설명을 선택적으로 등록하는 방식이 승인됐다. 본업·부업 구분을 강제하거나 두 개로 제한하지 않는다. 등록과 편지 공개는 별도 선택이며 세부 UI·입력 상한·활동별 인증은 미정이다.

- 상대 선호의 중요도·유연성은 운영자가 중요한 별도 상세 설계 과제로 지정했다. 이후 깊게 논의한다. 제안한 3단계 중요도·수집 방식·필수 여부·소개 적용은 아직 확정하지 않았다.

- 2026-11-06 재검토 9번. 갈피는 결혼을 생각한다고 답한 사람에게만 향후 자녀 의향을 묻는다. 이미 이야기했다면 소개 준비 때 그 답을 확인한다. ‘원해요 / 원하지 않아요 / 아직 모르겠어요’처럼 본인이 확인한 답만 소개 편지에 담고, 이유는 갈피와 나눈 대화에만 남긴다. 결혼 의향이 없거나 미정이라 질문을 건너뛴 경우에는 편지에서도 해당 항목을 생략한다. 결혼 관련 세부 가치관은 후속 설계에서 다룬다.

- 생활 시간대와 평소 만나기 편한 요일·시간대는 소개 전에 각각 확인한다. 대략적인 생활 리듬은 갈피가 주선에 참고하고, 편지에는 본인이 확인한 만나기 편한 시간대와 조율 여지를 간단히 담는다. 약속을 위해 평소 일정을 바꿀 수 있다는 점을 반영해 시간대를 선호 정보로 다룬다. 평소 시간대가 겹치지 않는다는 이유만으로 소개를 제외하지 않는다. 조율 가능한 정도도 본인에게 확인하며, 구체적인 약속은 두 사람이 정한다. 생활 시간대로 만남 가능 시간을 추정하거나 온라인 상태·답장 압박에 활용하지 않는다. 세부 선택지·갱신 방식은 후속 설계 대상이다.

- 음주 빈도·술자리 선호·상대 음주 습관 수용 범위를 소개 전에 각각 확인한다. 본인의 음주 빈도와 술자리 선호는 본인이 확인한 짧은 문장으로 소개 편지에 담는다. 상대의 음주 습관을 받아들일 수 있는 범위는 갈피가 소개할 상대를 고를 때만 사용한다.
- 갈피는 술자리 선호를 더 알아갈 때 먼저 대화를 열어 “보통 누구와 있을 때 술을 마시는 편이야?”처럼 물을 수 있다. ‘연인과만 마신다’, ‘친구 모임에서는 술을 마시지 않아도 자리는 즐긴다’처럼 관계와 상황을 이해한다. 이 맥락은 본인이 편지 문구로 확인한 경우에만 상대에게 전달한다.

- 본인 흡연 여부와 상대의 흡연을 어디까지 받아들일 수 있는지는 소개 전에 각각 확인한다. 소개 편지에는 본인의 흡연 여부를 표시한다. 상대의 흡연에 대한 선호와 조건은 갈피가 그 사람에게 소개할 상대를 고를 때만 사용한다. 전자담배·가끔 흡연 등 세부 선택지는 추후 정한다.

- 생활권·만남 가능한 범위·장거리 연애 의향은 소개 전에 별도로 확인한다. 생활권은 소개 준비 때 본인이 주로 생활하는 지역을 시·구 정도로 선택하고, 선택한 지역명을 선정된 상대의 소개 편지에 그대로 표시한다. 만날 수 있는 지역은 여러 곳을 선택할 수 있다. 갈피에게 이미 말한 곳은 소개 준비 때 정리해 보여주고 본인 확인만 받는다. 장거리 연애 의향은 ‘괜찮아요 / 상황에 따라 달라요 / 어려워요’로 확인한다. 이미 말한 의향은 확인만 받는다. ‘상황에 따라 달라요’와 ‘어려워요’ 모두 갈피가 먼저 대화를 열어 이동 시간이나 만남 빈도 등 무엇이 중요한지 더 알아갈 수 있다. ‘어려워요’라는 답은 본인이 바꾸기 전까지 소개 기준으로 존중한다.

- 새 소개는 현재 배우자와 연인이 모두 없는 경우에만 제공한다. 별거·이혼 절차 중이면 혼인 종료 뒤 시작한다. 미확인을 배우자·연인 없음으로 간주하지 않는다. 가입·갈피 이용과 기존 소개·대화 처리, 재확인·증빙 방법은 별도 결정한다.

- 후속 확정: 소개 전 현재 혼인 상태와 과거 이혼 경험을 확인한다. 교제 상태는 위 재검토 6번에 따라 별도 질문 없이 소개 이용 기준으로 안내한다. 이혼·사별 경험이 있는 사람도 소개 대상에 포함하고 서로의 재혼 상대 수용 의사를 확인해 연결한다. 증빙·공개 방식은 미정이다.
- 자녀 여부는 혼인 경험이 있는 사람에게만 묻는다. 혼인 경험이 없는 사람은 자기 정보에서 직접 추가할 수 있다. 질문 생략을 자녀 없음으로 간주하지 않는다. 자녀가 있다고 답하면 소개 전 동거 여부·직접 양육 여부를 각각 확인한다. 구체적 선택지와 공개·소개 적용은 별도 결정한다. 향후 자녀 의향은 현재 자녀 유무와 구분하며 위 결혼 의향 분기를 따른다.

- 후속 확정: 원하는 관계와 결혼 의향을 별개로 묻는다. 질문 순서·화면 배치·선택지·필수 범위·매칭 활용은 아직 미확정이다. 항목별로 하나씩 의논한다.

- 운영자 결정: 조건 정보는 가입 자격이 아니며 선택적으로 받는다. 본인의 자랑거리로 공개하고 싶은 사람은 항목별로 공개할 수 있게 한다.
- 운영자 결정: 사진은 소개 준비 단계에서 받는다. 이름·생활권만 받는 가입안은 아직 확정하지 않았다.
- 현행 설계: 신원 확인은 갈피 이용 전 필요하다. 학벌·소득·주거·회사명을 가입 자격이나 전체 노출 순위에 쓰지 않는다.
- 현행 설계: 조건 증빙은 선택이다. 허락한 항목에만 ‘확인됨’을 붙이며, 증빙하지 않았다는 이유로 ‘미인증’ 낙인을 붙이지 않는다. 확인한 항목·범위·시점을 구분한다.
- 현행 설계: 깊은 대화와 거절 이유는 상대에게 공개하지 않는다. 공개는 불특정 다수의 프로필 목록이 아니라 AI가 고른 상대에게 보내는 소개 편지 안에서 이뤄진다.

## 등록·확인·공개를 분리하는 제안

정보마다 다음 상태를 독립적으로 관리한다. 아직 스키마 변경안은 아니다.

| 구분 | 기록할 내용 | 사용자에게 주는 의미 |
| --- | --- | --- |
| 등록 | 미입력 / 답변 보류 / 직접 입력 / 대화에서 확인한 값 | 말하지 않음과 값이 없음을 구분. 대화 속 발언을 공개 프로필로 자동 등록하지 않음 |
| 출처 | 직접 답변 / 문서·기관 확인 / AI 해석 | AI가 추정한 것을 인증된 사실로 취급하지 않음 |
| 인증 | 미신청 / 확인 중 / 확인 완료 / 재확인 필요 / 확인 불가 | 내부 처리 상태. 상대에게 미신청·실패 표시를 그대로 노출하지 않음 |
| 확인 범위 | 무엇을 어떤 근거로 언제 확인했는지 | 재직 확인만으로 직급·연봉까지 인증됐다고 표시하지 않음 |
| 사용 목적 | 소개 판단 / 소개 편지 표시 등 | 비공개가 AI 판단에도 미사용이라는 뜻은 아님. 목적별 허용 범위 설명 필요 |
| 공개 | 항목별 공개 선택, 표시 수준, 본인이 확인한 문구 | 입력·인증만으로 자동 공개하지 않음. 전체 공개 스위치로 뭉치지 않음 |
| 갱신 | 값 변경, 증빙 유효성, 공개 문구 재확인 | 이직·이사 등으로 값이 바뀌면 이전 인증 표시를 그대로 붙이지 않음 |

예: 회사명은 등록하되 편지에는 재직 확인만 표시할 수 있다. 학교명은 공개하되 증빙은 신청하지 않을 수 있다. 소득은 선택한 구간만 공개할 수 있다. 이 조합을 지원하는 것이 추천안이며, 미증빙 사실을 편지에 담는 최종 표시 정책은 운영자 결정이 필요하다.

## 사용자 경험 배치 제안

1. **가입·진입:** 이용에 필요한 인증·동의와 최소 기본 정보를 받는다. 최소 항목은 전체 설계 확정 뒤 결정한다.
2. **갈피와 알아가기:** 생활 방식·성향·관계 의향을 점진적으로 이해한다. 사용자가 직접 정보 화면에서 추가·정정하는 길도 둔다.
3. **소개 준비:** 사진과 소개에 꼭 필요한 정보의 준비 상태를 확인한다. 조건·강점을 원하는 만큼 추가하고, 증빙과 공개 범위를 선택한다.
4. **내 소개 미리보기:** 실제 전달 형식으로 항목·표현·확인 표시를 검토한다. 공개하지 않은 항목은 빈칸이나 ‘비공개’ 목록으로 나열하지 않는 안을 추천한다.
5. **변경·갱신:** 정보 수정·공개 해제·증빙 재확인을 지원한다. 이미 전달된 편지에 변경을 어떻게 반영할지는 전달 시점 정책으로 별도 결정한다. 공개 해제가 상대의 기존 열람 기억까지 지운다고 약속하지 않는다.

## 인증·보관 운영 제약

- 현행 설계는 조건 증빙 원본을 확인 뒤 폐기하고 항목·구간·확인일 등 결과만 보관하는 방향이다. 접수 중 보관 기간·실패 시 삭제·접근 권한·처리 주체는 인증 방식 선택 때 구체화한다.
- 얼굴 사진·신분 확인·조건 서류의 처리를 하나로 묶지 않는다. 인증 업체·자동 판독·사람 검수 중 무엇을 쓸지 아직 정하지 않았다.
- 인증을 선택할 수 없는 사람이나 미등록자를 전체 노출에서 불리하게 만들지 않는다. 개인별 선호에 쓰는 범위와 전체 사용자 등급·순위를 구분한다.
- 새 외부 인증 서비스의 제공 범위·비용·정확도는 미확인이다. 선택 전 실제 자료를 조사하며 유료 호출·계정 생성은 별도 승인받는다.

## 결정 순서

종교까지 이번 정보 후보 목록 검토를 마쳤다. 이후 새 항목을 계속 추가하기보다 아래 전체 표를 기준으로 수집 방식(명시적 입력/갈피 대화/병행) 제안과 미결정 사항을 정리한다. 정보 후보 포함은 모든 항목의 필수 수집이나 구현 완료가 아니다. 이미 승인된 입력·선택·동의 원칙은 유지한다.

외형 추천은 별도 상세 설계 과제로 관리한다. 기존 하드룰대로 외모 신호는 개인별 적합성에만 쓰며 전체 회원 등급·노출 순위로 만들지 않는다. 사진·본인 입력·추정의 구분과 수락/넘김 이유의 불확실성을 상세 설계에서 다룬다. 사진으로 체형 등을 자동 추출하도록 승인한 것은 아니다.

운영자 후속 합의에 따라 아래 논의는 **정보 항목·목적 → 수집 방식(입력/대화/병행) → 수집 시점·화면 배치**의 순서로 진행한다. 현재 항목 검토 중 새 입력란까지 함께 확정하지 않는다. 이미 확정한 선택 등록·공개·질문 분기를 임의로 취소하지 않는다.

1. 최종 정보 영역과 누락 여부를 확인한다. 현재 확정은 조건 정보의 선택 등록·선택 공개와 사진 수집 시점이다.
2. 소개 준비에 꼭 필요한 정보와 선택 정보를 구분한다. 특히 혼인 상태·관계 의향·생활 방식의 필수 범위를 결정한다.
3. 조건 정보의 공개 표시를 정한다: 직접 입력도 공개하고 확인된 항목에만 표시할지, 특정 항목은 인증 후 공개할지.
4. 인증 범위·방식·갱신 주기·보관을 정하고 화면에 배치한다. 이 결과로 가입 구성안을 갱신한다.
