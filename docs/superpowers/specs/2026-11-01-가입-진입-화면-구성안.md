# 가입·동의·본인인증 화면 구성안

상태: 운영자 검토용 초안. 소개 준비 때 현재 얼굴을 알아볼 수 있는 본인 사진 한 장을 기본 프로필에 필수 등록한다. 화면 상세·문구는 아직 승인 전이다. 실제 인증·DB 연결 완료를 뜻하지 않는다.

## 현재 검토 범위

최신 운영자 요청에 따라 기존 모바일 앱의 스플래시·서비스 소개부터 다시 검토한다. 기존 흰 바탕·먹색 버튼·프리텐다드와 승인한 네 장의 문구·투명 삽화를 적용했다. 실제 앱은 시작 → 스플래시 → 서비스 소개로 연결되며, 토큰을 보유한 경우에는 기존처럼 친구 화면으로 간다. 웹 미리보기에서 장 넘기기·가입/로그인 진입·휴대폰과 PC 배치를 확인했다. 네이티브 기기 실행과 실제 인증은 미확인이다.

서비스 소개의 시작하기·건너뛰기는 기존 가입 화면, 로그인은 기존 로그인 화면으로 이어진다. 이 화면은 모의 인증 입력이 남은 기존 코드로, 다음에 동의·인증 상세를 의논할 대상이다. 아래 HTML 시안과 최신 가입 흐름 전체를 실제 모바일에 적용한 상태로 혼동하지 않는다.

갈피의 페르소나·운영 모델·후속 응답 구현은 후속 논의에서 정한다. 시안의 카드 문구와 항목 배치는 검토용이며 필수 항목이나 질문 순서를 확정하지 않는다.

`docs/previews/onboarding/index.html`에서 다음 흐름을 눌러 볼 수 있다. 시안 상단의 ‘화면 이동’은 검토할 화면을 바로 여는 도구다.

| 흐름 | 화면 구성과 행동 |
| --- | --- |
| 가입 진입 | 서비스 소개 네 장 → 가입 동의 → 모의 본인인증 → 대화 동의 |
| 갈피 첫 만남 | 기존 인사 말풍선, 내 소개 준비 카드, 자유 답장 입력창, 홈으로 이동 |
| 내 소개 준비 | 지역·일/활동 편집 자리, 대표·추가 사진, 입력한 내용 확인, 갈피 대화로 복귀 |
| 첫 홈 | 갈피 대화 진입 카드와 내 소개 준비 바로가기 |
| 대화 탭 | 갈피와의 같은 대화로 이동, 마지막으로 입력한 답장 표시 |
| 내 이야기 탭 | 정리된 이야기가 없는 첫 방문 상태, 갈피 대화와 내 소개로 이동 |
| 설정 탭 | 계정·알림·개인정보와 동의·도움말 항목의 자리 |

첫인사부터 답장 없이 홈으로 갈 수 있고 갈피를 누르면 같은 대화가 이어진다. 사용자 답장이나 프로필 편집으로 갈피의 답변·분석 결과를 생성하지 않는다. 현재 입력과 사진 미리보기는 페이지 메모리에서만 유지되며 새로고침하면 초기화된다. 사진은 외부로 전송하지 않는다.

지역·일/활동·사진은 배치와 이동을 확인하기 위한 대표 항목이다. 전체 정보 설계표의 수집·확인·선택 공개 원칙을 대체하지 않으며, 처음 채울 항목과 필수 여부는 별도로 의논한다.

운영자 후속 요청: 가입 입력을 먼저 최소화하지 않고 [최종 사용자 정보 설계표](2026-11-01-최종-사용자-정보-설계표.md)에서 최종 확보 정보·인증·선택 공개를 먼저 정한다. 아래 이름·생활권 중심 배치는 확정안이 아니며 전체 정보 구조 결정 후 갱신한다. 조건 정보는 선택적으로 등록하고 자신의 강점으로 공개할 수 있게 한다.

## 확정된 내용과 현재 구현

- 초기 설계의 진입 순서는 가입 → 분리 동의 → 본인인증 → 갈피 첫 만남이다. 본인인증 전에 갈피와 대화하지 않는다. 당시 기본 정보·사진 위치는 미결정으로 남겼다([갈피 설계 9장](2026-10-11-갈피-AI-엔진-design.md)).
- 가입에서 학벌·연봉·주거·회사명을 자격 조건으로 받지 않는다. 동의·인증 화면은 담백한 시스템 문구를 쓴다.
- 현재 모바일 시작점은 스플래시와 승인한 서비스 소개다. 기존 로그인 화면은 모의 인증 입력을 포함하고 있어서 그대로 사용자 가입 화면으로 쓸 수 없다. 이번 변경은 가입·로그인 진입 영역을 구분하며, 인증 API와 저장 계약을 바꾸지 않았다.
- 인증 API는 인증 완료 때 가입 또는 로그인을 처리한다. 제품의 ‘가입 시작’과 계정 생성 시점은 구분한다. 기존 다음 단계에는 옛 얼굴 인증·홈 단계가 남아 있어 현재 화면 흐름과 대조가 필요하다.
- 갈피 접근 서비스는 인증과 AI 필수 동의를 확인한다. 옛 화면 설계의 ‘민감정보 동의 없이 대화 가능’ 설명과 현재 코드가 다르다. 이 초안에서 옛 선택 동의를 그대로 구현하지 않는다. 동의 범위·거부 시 동선·최종 고지문은 별도로 확인할 미결정 사항이다.

## 화면 흐름 — 가입 후 갈피 첫 대화

시작 → 가입 동의(서비스 이용약관·개인정보 수집 및 이용) → 본인인증 → 대화 직전 별도 동의(민감정보 처리·개인정보 국외 이전) → 갈피 첫 만남.

실제 소개를 시작하려면 현재 얼굴을 알아볼 수 있는 본인 사진 한 장을 대표 사진으로 등록한다. 기본 프로필에는 사진을 원하는 만큼 더 올릴 수 있다. 소개 편지에는 대표 사진을 비롯한 프로필 사진 전체가 들어가고, 해당 편지에만 보여주고 싶은 사진도 원하는 만큼 첨부할 수 있다. 검수 방식은 후속 설계에서 정한다.

| 화면 | 위에서 아래로 배치할 내용 | 주요 행동 | 상태·예외 |
| --- | --- | --- | --- |
| 시작 (검토 시안) | 옆으로 넘기는 네 장: 서비스 소개 → 갈피와 알아가기 → 편지와 상호 수락 → 만남 후 대화. 스와이프와 현재 장 표시 | 상단 로그인 · 1~3장 다음 / 건너뛰고 시작하기 · 마지막 장 시작하기 | 첫 방문자는 첫 장부터 읽고 원하는 시점에 가입으로 이동 |
| 가입 동의 | 서비스 이용약관·개인정보 수집 및 이용의 목적, 항목별 체크와 상세 보기, 진행 안내 | 각 동의 확인 후 계속 | 미선택, 상세 문서 로딩 실패, 뒤로 갔다 복귀, 동의 저장 실패 |
| 본인인증 안내 | 성인 여부·본인 확인 목적, 인증기관 이동 안내, 인증 버튼 | 본인인증 시작 | 인증 시작 중 중복 누름 방지, 외부 화면 취소 |
| 인증 결과 | 성공 시 다음 단계로 이동, 실패 시 이유 범주와 재시도 | 다시 인증하기 / 돌아가기 | 시간 초과, 결과 확인 지연, 미성년·이용 제한. 원본 인증정보는 노출하지 않음 |
| 대화 직전 동의 | 민감정보 처리와 개인정보 국외 이전을 별도 항목으로 설명 | 각각 확인 후 갈피와 대화하기 | 두 동의 전에는 대화를 시작하지 않는다. 최종 고지문과 거부 시 동선은 후속 검토 |
| 첫 만남 | 기존 인사, 내 소개 준비 카드와 자유 답장 입력창 | 프로필 준비 / 답장 / 홈으로 | 중간에 나가도 같은 대화로 돌아온다. 페르소나·응답 방식·질문 순서는 후속 논의 |
| 기본 프로필 사진 | 필수 본인 사진 한 장, 추가 사진 선택, 미리보기 | 사진 선택·교체 후 소개 준비 계속 | 필수 사진 미등록, 업로드 실패·재시도 |

성별·나이는 인증에서 확인한 정보와 중복 입력하지 않는 안을 우선 검토한다. 실제 인증 제공자가 주는 항목과 저장 계약 확인 전 확정하지 않는다. 직군 등 추가 입력의 필수 여부도 이번 초안에서 늘리지 않는다.

## 문구 초안

- 시작 화면 제목: ‘내 프로필은 모두에게 공개되지 않아요.’
- 시작 설명: ‘프롤로그에서는 소개받는 한 사람에게만 내 프로필이 편지로 전해져요.’
- 두 번째 장 설명: ‘나를 잘 아는 친구에게 소개팅을 받듯이, AI 친구 갈피가 내 이야기를 듣고 잘 맞을 만한 사람을 소개해요.’
- 이미지 표현: 가입 흐름의 갈피와 삽화는 윤곽 밖을 투명하게 표시해 앱 화면의 바탕색이 자연스럽게 이어지게 한다.
- 인증 설명: ‘프롤로그는 성인만 이용할 수 있어요. 시작하기 전에 본인인증을 진행해 주세요.’
- 가입 때는 이름을 입력하지 않는다. 첫 소개 편지를 준비할 때 갈피가 닉네임을 추천하고, 사용자가 그대로 쓰거나 원하는 닉네임·본명을 직접 적어 편지에 표시할 이름을 정한다.
- 인증 취소: ‘인증을 마치지 않았어요. 준비되면 다시 진행해 주세요.’
- 일시 오류: ‘지금은 확인을 마치지 못했어요. 잠시 후 다시 시도해 주세요.’

위 문구는 검토용이며 약관·개인정보 고지문이 아니다. 최종 동의 문안과 인증 제공자 표시는 별도 확인 후 시안에 넣는다.

## 구현 전에 연결할 계약

- 로그인: 기존 카카오·휴대폰 로그인 경로와 모바일 OAuth를 현행 흐름에 연결한다. 기존 토큰·세션 정보를 화면과 로그에 표시하지 않는다.
- 인증: 시작·완료 API의 성공/취소/대기/실패를 분리한다. 클라이언트의 ‘성공’ 표시만으로 인증 완료를 인정하지 않는다.
- 동의: 종류·버전·동의 여부를 서버가 확인한다. 최신 동의와 철회 이력은 기존 갈피 접근 조건과 일치시킨다.
- 기본 정보: 표시 이름·생활권 저장 계약과 재개 상태를 확인한다. 기존 사용자는 저장된 완료 상태에 따라 필요한 단계만 이어 간다.
- 사진: 기본 프로필 사진은 소개 준비 때 등록하고, 소개 편지에 첨부할 사진은 별도로 선택한다. 인증·사진 검수·소개 준비 상태를 하나로 취급하지 않는다.

## 다음 결정과 완료 조건

기본 프로필 사진 등록 시점은 **소개 준비 때**로 확정했다. 최신 요청에 따라 기존 앱의 스플래시·서비스 소개를 먼저 보고 이어지는 가입·동의·본인인증 화면을 하나씩 의논한다. 처음 채울 정보 범위와 동의 화면의 미결정 부분도 개별 결정한다.

구성안 확정 → 폰·PC 시안 확인 → 구현·서버 연결 → 정상·중단·실패·재접속 흐름 확인까지 수행한다. DB 적용·외부 호출 비용·운영 배포는 별도 승인 범위다. 현재 실제 모바일에 반영한 범위는 스플래시·서비스 소개와 기존 가입·로그인 진입이며, 비밀값과 외부 인증은 사용하지 않았다.
