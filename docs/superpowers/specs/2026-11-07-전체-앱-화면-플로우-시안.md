# 전체 앱 화면과 플로우 시안

상태 — 운영자 검토용. 현행 설계와 최근 대화에서 합의한 방향을 페이지와 기능 단위로 배치했다. 현재 시안은 앱 화면 78개와 검토 화면 2개로 구성한다. 기능·정책 확정 및 실제 서비스 연결은 개별 검토한다.

## 검토하는 방법

- 미리보기에서 ‘전체 흐름’을 열면 기능별 화면을 찾거나 가입·편지 도착·연결 이후·만남 이후 경로로 들어간다.
- 상단 ‘미리볼 상태’에서 첫 방문, 소개 준비 후, 이야기 선택, 편지 도착, 내 수락 후 대기, 서로 수락, 대화 성립, 약속 확정, 만남 다음 날, 편지 닫힘을 선택한다.
- ‘결정 필요’에서 페르소나·응답 방식 등을 따로 의논한다.
- 편지·상대·리포트·기억·연결권 내역은 화면 검토용 예시다. 입력·체크·사진은 현재 페이지 메모리에서만 유지되고 새로고침하면 초기화된다.

## 현행 설계에서 가져온 기준

- 본인·성인 인증과 대화 동의를 거쳐 갈피를 만난다. 첫인사부터 답장 없이 홈으로 갈 수 있고 같은 갈피 대화로 돌아온다.
- 친구·대화·내 이야기·설정 네 탭을 사용한다. 홈은 내 프로필 → 중요한 일 → 친구 목록 → 소식 순서다. 갈피 행은 기존 대화로, 사진은 갈피의 방으로 연결한다. 중요한 일과 소식은 항목이 있을 때 표시한다. [친구 홈 확정 결정](../../decisions/2026-11-07-친구-홈-구성과-진입.md)을 따른다.
- 갈피 첫 대화에는 내 소개 준비 카드를 배치했다. 처음 채울 항목·순서·필수 범위와 대화 속 수집 방식은 운영자 결정 과제로 남긴다.
- 이름은 첫 소개 편지를 준비할 때 정한다. 갈피의 닉네임 추천 자리와 직접 입력을 표시한다. 인증 실명을 자동으로 채우지 않는다.
- 대표 사진은 실제 소개 준비 때 등록한다. 프로필 사진 전체와 특정 편지에만 추가하는 첨부 사진을 구분한다.
- 생활·혼인·자녀·관계 의향, 상대 선호, 선택 조건 정보를 별도 화면에 배치한다. 선택 등록과 편지 공개를 분리한다. 민감한 종교 정보는 별도 동의 자리 뒤에 선택 입력을 둔다.
- 공개 프로필을 둘러보는 화면을 두지 않는다. 두 이야기 선택 후 한 편지를 여는 경로와 한 편지가 바로 도착하는 경로를 각각 표현한다.
- 편지 수락 후 상대 답을 기다린다. 서로 수락하면 두 사람의 대화가 열린다. 수락·대화방 개설 시 연결권을 차감하지 않고 대화 성립 상태에서 사용되는 예시를 둔다.
- 넘긴 소개에 대한 생각은 갈피 대화 안에서 선택으로 남긴다. 넘기거나 닫힌 편지의 사진은 다시 열리지 않는다.
- 앱 내 통화, 만남 제안·수정·취소와 양쪽 확인 대기 상태를 둔다. 연락처 교환은 대화 메뉴 안쪽에서 양쪽 동의와 직접 공개를 준비하는 자리다.
- 상대와의 대화에 읽음·온라인 상태·만료를 넣지 않는다. 갈피는 두 사람의 대화를 읽지 않는다는 안내를 둔다.
- 만남 후 본인이 선택한 피드백을 확인한다. 원문과 거절 이유는 상대에게 공개하지 않는다.
- 내 이야기에는 서고·기억 확인/빼기·리포트 준비/도착·취향 카드·발견한 것이 있다. 갈피의 방·기념품·소품의 자리도 분리한다.
- 가벼운 소개는 기본 꺼짐이며 동의한 사람끼리만 주고받는 설정을 둔다. 새 편지 쉬기와 기존 대화 유지도 표현한다.

근거는 [서비스 구성과 위계](2026-10-10-서비스-구성-위계-design.md), [현행 사용자 정보 설계표](2026-11-01-최종-사용자-정보-설계표.md), [가입 구성안](2026-11-01-가입-진입-화면-구성안.md)와 최근 운영자 결정이다. 옛 화면 흐름과 충돌하는 최신 결정은 위 기준을 우선한다.

## 의사결정 대기

1. 갈피의 응답 방식 — 고정형·모델·혼합, 운영 모델, 평가 기준.
2. 페르소나와 대화 — 말투·첫 질문·질문 순서·먼저 말 걸기·중단/재개.
3. 첫 프로필 — 필수 항목·건너뛰기·처음에 채울 범위·소개 준비 완료 기준.
4. 인증 — 본인·사진·조건 정보의 제공자·검수·증빙·실패·재시도.
5. 동의와 정보 처리 — 최종 문안·거부·철회·가명처리·보관·삭제.
6. 주선 — 선호 중요도·유연성·본인 확인한 제외 기준·외형 정보 활용.
7. 연결권 — 상품·가격·대화 성립 기준·잔여가 없을 때 처리·환불·복원.
8. 안전 — 신고 처리·이의 제기·차단/종료 후 기록·종료 후 신고.
9. 만남과 연락처 — 약속 변경/취소의 양쪽 확인·통화 제공 방식·연락처 동의/공개.
10. 학습·기억·리포트 — 구조화한 정보의 본인 확인·삭제 영향·갱신.
11. 알림과 기기 권한 — 문구·빈도·기본값·요청 시점·거부 시 동선.
12. 편지와 부가 기능 — 인증 표시·선택 공개·가벼운 소개 상한·취향 카드·소품.
13. 외부 약속 공유 — 도입 여부·상대 정보 제공 범위·동의.

## 실행 범위와 확인

정적 시안은 화면 간 이동과 입력·사진·예시 상태 전환을 제공한다. 실제 모델 선택·프롬프트·응답 생성·추출·추천 로직은 후속 구현 과제다. 외부 인증·사진 업로드·DB·과금·신고 접수·마이크·연락처 접근·푸시·탈퇴도 후속 연결 과제다.

휴대폰 폭에서 전체 화면의 진입점과 수평 넘침, 주요 화면의 PC 폭을 확인했다. 가입 → 모의 인증 → 대화 동의 → 첫 대화 → 홈, 선택 정보 공개, 조건부 가족 질문, 프로필/편지 사진 구분, 수락 시 차감 없음, 서로 수락 후 대화, 약속 확인 대기, 대화 성립 상태, 넘김 후 사진 닫힘, 가벼운 소개의 동의, 비공개 피드백 확인, 기억 빼기, 연결 종료 후 신고를 실행으로 확인했다.
