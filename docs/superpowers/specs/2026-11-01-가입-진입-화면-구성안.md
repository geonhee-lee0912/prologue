# 가입·동의·본인인증 화면 구성안

상태: 운영자 검토용 초안. 가입 때 현재 얼굴을 알아볼 수 있는 본인 사진 한 장을 기본 프로필에 필수 등록한다. 화면 상세·문구는 아직 승인 전이다. 실제 인증·DB 연결 완료를 뜻하지 않는다.

운영자 후속 요청: 가입 입력을 먼저 최소화하지 않고 [최종 사용자 정보 설계표](2026-11-01-최종-사용자-정보-설계표.md)에서 최종 확보 정보·인증·선택 공개를 먼저 정한다. 아래 이름·생활권 중심 배치는 확정안이 아니며 전체 정보 구조 결정 후 갱신한다. 조건 정보는 선택적으로 등록하고 자신의 강점으로 공개할 수 있게 한다.

## 확정된 내용과 현재 구현

- 현행 진입 순서는 가입 → 분리 동의 → 본인인증 → 갈피 첫 만남이다. 본인인증 전에 갈피와 대화하지 않는다. 당시 기본 정보·사진 위치는 미결정으로 남겼다([갈피 설계 9장](2026-10-11-갈피-AI-엔진-design.md)).
- 가입에서 학벌·연봉·주거·회사명을 자격 조건으로 받지 않는다. 동의·인증 화면은 담백한 시스템 문구를 쓴다.
- 현재 모바일 시작점은 mock 갈피 흐름이다. 기존 로그인 화면은 모의 인증 입력을 포함하고 있어서 그대로 사용자 가입 화면으로 쓸 수 없다.
- 인증 API는 인증 완료 때 가입 또는 로그인을 처리한다. 제품의 ‘가입 시작’과 계정 생성 시점은 구분한다. 기존 다음 단계에는 옛 얼굴 인증·홈 단계가 남아 있어 현재 화면 흐름과 대조가 필요하다.
- 갈피 접근 서비스는 인증과 AI 필수 동의를 확인한다. 옛 화면 설계의 ‘민감정보 동의 없이 대화 가능’ 설명과 현재 코드가 다르다. 이 초안에서 옛 선택 동의를 그대로 구현하지 않는다. 동의 범위·거부 시 동선·최종 고지문은 별도로 확인할 미결정 사항이다.

## 화면 흐름 — 가입 때 기본 프로필 사진 등록

시작 → 동의 확인 → 본인인증 → 최소 기본 정보·기본 프로필 사진 등록 → 갈피 첫 만남.

가입을 마치려면 현재 얼굴을 알아볼 수 있는 본인 사진 한 장을 등록한다. 기본 프로필에 사진을 더 올리는 것은 선택이다. 소개 편지의 사진 첨부는 별도 선택으로 둔다. 검수 방식과 추가 장수는 후속 설계에서 정한다.

| 화면 | 위에서 아래로 배치할 내용 | 주요 행동 | 상태·예외 |
| --- | --- | --- | --- |
| 시작 | 프롤로그 이름, 서비스 설명 한 문장, 시작 버튼, 기존 이용자 로그인 | 시작하기 / 로그인 | 로그인 취소·실패, 기존 사용자 복귀, 이용 제한 |
| 동의 확인 | 필요한 이유, 항목별 체크와 상세 보기, 진행 안내 | 각 동의 확인 후 계속 | 미선택, 상세 문서 로딩 실패, 뒤로 갔다 복귀, 동의 저장 실패 |
| 본인인증 안내 | 성인 여부·본인 확인 목적, 인증기관 이동 안내, 인증 버튼 | 본인인증 시작 | 인증 시작 중 중복 누름 방지, 외부 화면 취소 |
| 인증 결과 | 성공 시 다음 단계로 이동, 실패 시 이유 범주와 재시도 | 다시 인증하기 / 돌아가기 | 시간 초과, 결과 확인 지연, 미성년·이용 제한. 원본 인증정보는 노출하지 않음 |
| 최소 기본 정보 | 갈피가 부를 이름, 생활권, 인증으로 확인된 항목의 필요한 안내 | 기본 정보 저장 | 입력 오류, 저장 실패·재시도, 중단 후 재개. 정확한 주소는 받지 않음 |
| 기본 프로필 사진 | 필수 본인 사진 한 장, 추가 사진 선택, 미리보기 | 사진 선택·교체 후 가입 완료 | 필수 사진 미등록, 업로드 실패·재시도 |
| 첫 만남으로 연결 | 갈피 대화방 진입 | 첫 인사 받기 | 시작 중 오류·재시도, 이미 시작한 대화 이어가기. 상세는 다음 ROADMAP 작업 |

성별·나이는 인증에서 확인한 정보와 중복 입력하지 않는 안을 우선 검토한다. 실제 인증 제공자가 주는 항목과 저장 계약 확인 전 확정하지 않는다. 직군 등 추가 입력의 필수 여부도 이번 초안에서 늘리지 않는다.

## 문구 초안

- 시작 설명: ‘갈피와 이야기하며 나를 알아가고, 좋은 상대가 나타나면 소개를 받아요.’
- 인증 설명: ‘프롤로그는 성인만 이용할 수 있어요. 시작하기 전에 본인인증을 진행해 주세요.’
- 이름 입력: ‘갈피가 어떻게 불러드릴까요?’
- 인증 취소: ‘인증을 마치지 않았어요. 준비되면 다시 진행해 주세요.’
- 일시 오류: ‘지금은 확인을 마치지 못했어요. 잠시 후 다시 시도해 주세요.’

위 문구는 검토용이며 약관·개인정보 고지문이 아니다. 최종 동의 문안과 인증 제공자 표시는 별도 확인 후 시안에 넣는다.

## 구현 전에 연결할 계약

- 로그인: 기존 카카오·휴대폰 로그인 경로와 모바일 OAuth를 현행 흐름에 연결한다. 기존 토큰·세션 정보를 화면과 로그에 표시하지 않는다.
- 인증: 시작·완료 API의 성공/취소/대기/실패를 분리한다. 클라이언트의 ‘성공’ 표시만으로 인증 완료를 인정하지 않는다.
- 동의: 종류·버전·동의 여부를 서버가 확인한다. 최신 동의와 철회 이력은 기존 갈피 접근 조건과 일치시킨다.
- 기본 정보: 표시 이름·생활권 저장 계약과 재개 상태를 확인한다. 기존 사용자는 저장된 완료 상태에 따라 필요한 단계만 이어 간다.
- 사진: 기본 프로필은 가입 때 등록하고, 소개 편지에 첨부할 사진은 별도로 선택한다. 인증·사진 검수·소개 준비 상태를 하나로 취급하지 않는다.

## 다음 결정과 완료 조건

기본 프로필 사진 등록 시점은 **가입 때**로 확정했다. 다음은 최소 기본 정보의 항목과 동의 화면의 미결정 부분을 순서대로 의논한다.

구성안 확정 → 폰·PC 시안 확인 → 구현·서버 연결 → 정상·중단·실패·재접속 흐름 확인까지 수행한다. DB 적용·외부 호출 비용·운영 배포는 별도 승인 범위이며, 현재는 비밀값 없는 문서 설계 단계다.
