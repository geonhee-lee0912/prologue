# 최종 사용자 정보 설계표

상태: 전체 구조 검토용 초안. 운영자가 승인한 원칙과 아래 제안을 구분한다. 구현·인증 제공자 연결·법적 검토 완료를 뜻하지 않는다.

제품의 기본은 소개팅 앱이며 깊이 있는 주선으로 결정사의 대안이 될 수 있도록 한다. [확정 컨셉](../../decisions/2026-11-01-소개팅앱과-깊이있는-주선.md)을 따른다. [결정사 공식 자료 조사와 소개 전 필수 정보 추천안](../../research/2026-11-01-결정사-정보수집과-소개준비.md)은 검토 근거이며, 필수 후보는 하나씩 운영자가 결정한다.

## 목표와 확정 원칙

- 본인 흡연 여부와 상대 흡연 수용 여부는 소개 전에 각각 확인한다. 본인의 상태로 상대 수용 의사를 추정하지 않는다. 전자담배·가끔 흡연 등 구체적인 선택지와 소개 적용 방식은 미정이다.

- 생활권·만남 가능한 범위·장거리 연애 의향은 소개 전에 별도로 확인한다. 생활권은 시·구 정도이며 정확한 주소는 요구하지 않는다. 만남 가능한 범위만으로 장거리 연애 의향을 추정하지 않는다. 세부 선택지·거리 기준·소개 적용 방식은 미정이다.

- 새 소개는 현재 배우자와 연인이 모두 없는 경우에만 제공한다. 별거·이혼 절차 중이면 혼인 종료 뒤 시작한다. 미확인을 배우자·연인 없음으로 간주하지 않는다. 가입·갈피 이용과 기존 소개·대화 처리, 재확인·증빙 방법은 별도 결정한다.

- 후속 확정: 소개 전 현재 혼인·교제 상태와 과거 이혼 경험을 확인한다. 이혼·사별 경험이 있는 사람도 소개 대상에 포함하고 서로의 재혼 상대 수용 의사를 확인해 연결한다. 증빙·공개 방식은 미정이다.
- 자녀 여부는 혼인 경험이 있는 사람에게만 묻는다. 혼인 경험이 없는 사람은 자기 정보에서 직접 추가할 수 있다. 질문 생략을 자녀 없음으로 간주하지 않는다. 자녀가 있다고 답하면 소개 전 동거 여부·직접 양육 여부를 각각 확인한다. 구체적 선택지, 공개·소개 적용, 향후 자녀 계획은 별도 결정한다.

- 후속 확정: 원하는 관계와 결혼 의향을 별개로 묻는다. 질문 순서·화면 배치·선택지·필수 범위·매칭 활용은 아직 미확정이다. 항목별로 하나씩 의논한다.

최종적으로 사용자를 자세히 이해하고, 확인할 수 있는 사실은 인증 근거를 갖춘다. 가입 화면을 먼저 최소화하지 않고 최종 정보 구조를 정한 뒤 수집 시점을 배치한다.

- 운영자 결정: 조건 정보는 가입 자격이 아니며 선택적으로 받는다. 본인의 자랑거리로 공개하고 싶은 사람은 항목별로 공개할 수 있게 한다.
- 운영자 결정: 사진은 소개 준비 단계에서 받는다. 이름·생활권만 받는 가입안은 아직 확정하지 않았다.
- 현행 설계: 신원 확인은 갈피 이용 전 필요하다. 학벌·소득·주거·회사명을 가입 자격이나 전체 노출 순위에 쓰지 않는다.
- 현행 설계: 조건 증빙은 선택이다. 허락한 항목에만 ‘확인됨’을 붙이며, 증빙하지 않았다는 이유로 ‘미인증’ 낙인을 붙이지 않는다. 확인한 항목·범위·시점을 구분한다.
- 현행 설계: 깊은 대화와 거절 이유는 상대에게 공개하지 않는다. 공개는 불특정 다수의 프로필 목록이 아니라 AI가 고른 상대에게 보내는 소개 편지 안에서 이뤄진다.

## 정보별 목표 — 필수 여부·시점은 제안

‘필수 후보’는 운영자 결정 전이다. 선택 조건 정보에 대한 필수화 제안은 포함하지 않는다. 인증 방법은 검토 후보이며 현재 이용 가능한 제공자·계약·비용은 미확인이다.

| 영역 | 최종 확보하려는 항목 | 필요성과 수집 방식 | 필수 여부·시점 제안 | 확인 수준·상대 공개 |
| --- | --- | --- | --- | --- |
| 신원 | 본인 여부, 성인 여부, 중복 가입 확인 결과 | 이용 자격·계정 보호. 인증 제공자의 검증 결과 | 현행 필수, 갈피 이용 전 | 신원 확인 사실만. 이름·생년월일 원본·전화번호·내부 식별자는 공개하지 않음 |
| 기본 소개 | 부를 이름, 나이, 생활권, 만남 가능 범위, 장거리 연애 의향, 소개 대상과 관련된 기본 항목 | 생활권·만남 범위·장거리 의향은 별도로 직접 확인. 인증 결과와 직접 입력 구분 | 생활권·만남 범위·장거리 의향은 소개 전 확인으로 확정. 나머지 필수 범위와 실제 질문 배치는 미정 | 생활권은 시·구 정도, 정확한 주소는 요구하지 않음. 만남 범위·장거리 의향의 상대 공개 방식은 별도 결정 |
| 사진 | 현재 모습, 본인 사진 여부, 갱신 시점 | 소개 편지에 필요한 외모 정보. 본인 사진 등록 | 소개 준비 때 받기로 확정. 장수·검수·완료 요건 미정 | 소개 상대에게만. 사진 검수와 신원 인증을 동일시하지 않음 |
| 관계 의향 | 연애·결혼 의향, 희망 시기, 자녀에 대한 향후 계획 | 방향이 다른 소개를 줄임. 구조화 질문과 대화 | 소개 준비 전 확인할 필수 후보. 답변 선택지·미정 허용 범위 결정 필요 | 본인이 확인한 소개 요약. 건강·성생활·임신 가능성을 추론하거나 질문하지 않음 |
| 혼인·가족 상황 | 현재 혼인·교제 상태, 과거 혼인 이력, 자녀 여부·동거·직접 양육 | 소개 전 혼인·교제 상태와 이혼 경험 확인. 자녀 질문은 혼인 경험이 있는 사람에게만, 그 외에는 직접 추가 가능. 자녀가 있으면 동거·직접 양육을 별개로 확인 | 자녀 질문 분기와 후속 확인 항목은 확정. 세부 입력 시점·선택지·증빙은 미정 | 미확인을 자녀 없음으로 표시하지 않음. 제3자 이름·문서 원문은 제외, 세부 공개 범위 별도 결정 |
| 생활 방식 | 본인 흡연 여부·상대 흡연 수용 여부, 음주 습관, 활동 시간, 휴일 | 실제 만남과 일상 적합성. 본인 상태와 상대 수용 의사를 별도로 확인 | 흡연의 두 항목은 소개 전 확인으로 확정. 음주·시간 등은 제안 단계 | 흡연 등 실용 정보와 더 깊은 생활 이야기를 구분. 대화 원문은 공개하지 않음. 세부 선택지·소개 적용 방식은 별도 결정 |
| 일·재직 | 직군, 하는 일, 회사명, 직급, 재직 확인 | 일상 이해와 원하는 강점 표현. 직접 등록·대화 보완 | 회사명·직급 등 조건 정보는 선택. 알아가기/소개 준비 때 | 재직 사실 배지와 회사명 공개를 분리. 회사 이메일·서류 등 방식 후보는 검토 필요 |
| 학력 | 학교, 전공, 학위, 재학/졸업 상태 | 본인이 드러내고 싶은 이력과 선호 맥락 | 선택 등록·선택 증빙·선택 공개 | 이메일 소유가 졸업 증명은 아님. 실제 확인한 범위만 표시 |
| 소득 | 본인이 선택한 소득 구간, 소득 기준 기간·종류 | 생활 계획 이해와 선택적 강점 표현 | 선택 등록·선택 증빙·선택 공개 | 현행 방향은 구간 표시. 과거 소득 증빙이 현재 연봉을 보장하지 않음. 정확한 금액 원본은 공개하지 않음 |
| 주거 | 독립/동거 등 생활 형태, 본인이 밝히려는 주거 형태 | 생활 방식·향후 계획과 선택적 강점 표현 | 선택 등록·선택 공개. 증빙 범위 미정 | 거주·소유·자산가치는 서로 다름. 주소나 가족 정보를 드러내지 않는 표시 범위 설계 |
| 관심사·강점 | 취미, 꾸준히 하는 활동, 자격·경험, 자신 있게 말할 특징 | 조건 이외에도 사람을 설명할 재료 확보 | 선택. 직접 추가하거나 갈피와 대화 | 확인 가능한 자격과 주관적 강점을 구분. 과장 없는 본인 확인 소개 요약 |
| 관계 성향 | 대화·갈등 해결·애정 표현·혼자 있는 시간에 대한 선호 | 갈피의 깊은 이해. 사례 대화와 본인 정정 | 알아가기 동안 점진 축적. 강제 문항 완주를 요구하지 않는 안 | ‘인증’ 대상 아님. AI 해석을 사실로 확정하지 않음. 상대에게는 원문 아닌 허용된 소개 이유만 |
| 상대 선호 | 중요 기준, 조율 가능한 기준, 생활권·관계 방향 | 개인별 소개 판단. 본인의 명시적 선택과 대화 | 소개 준비 전 확인 제안, 이후 수정 가능 | 상대에게 원본 조건 목록·점수·거절 이유를 공개하지 않음 |
| 만남 후 경험 | 편했던 점, 불편했던 점, 다음 소개에 반영할 점 | 이후 소개 개선. 본인 피드백 | 만남 이후 선택 | 상대에게 피드백 원문·거절 이유 공개 금지. 선호 추정과 직접 답변 구분 |

민감정보는 ‘자세히 받기’라는 이유로 수집 범위를 넓히지 않는다. 기존 지침상 직접 묻지 않는 항목은 위 목표에서 제외한다. 종교 등 기존 별도 동의 범위의 구조화 항목은 동의 화면 설계와 함께 별도 검토한다. 이 문서는 적법성 판단이나 동의 문안이 아니다.

## 등록·확인·공개를 분리하는 제안

정보마다 다음 상태를 독립적으로 관리한다. 아직 스키마 변경안은 아니다.

| 구분 | 기록할 내용 | 사용자에게 주는 의미 |
| --- | --- | --- |
| 등록 | 미입력 / 답변 보류 / 직접 입력 / 대화에서 확인한 값 | 말하지 않음과 값이 없음을 구분. 대화 속 발언을 공개 프로필로 자동 등록하지 않음 |
| 출처 | 직접 답변 / 문서·기관 확인 / AI 해석 | AI가 추정한 것을 인증된 사실로 취급하지 않음 |
| 인증 | 미신청 / 확인 중 / 확인 완료 / 재확인 필요 / 확인 불가 | 내부 처리 상태. 상대에게 미신청·실패 표시를 그대로 노출하지 않음 |
| 확인 범위 | 무엇을 어떤 근거로 언제 확인했는지 | 재직 확인만으로 직급·연봉까지 인증됐다고 표시하지 않음 |
| 사용 목적 | 소개 판단 / 소개 편지 표시 등 | 비공개가 AI 판단에도 미사용이라는 뜻은 아님. 목적별 허용 범위 설명 필요 |
| 공개 | 항목별 공개 선택, 표시 수준, 본인이 확인한 문구 | 입력·인증만으로 자동 공개하지 않음. 전체 공개 스위치로 뭉치지 않음 |
| 갱신 | 값 변경, 증빙 유효성, 공개 문구 재확인 | 이직·이사 등으로 값이 바뀌면 이전 인증 표시를 그대로 붙이지 않음 |

예: 회사명은 등록하되 편지에는 재직 확인만 표시할 수 있다. 학교명은 공개하되 증빙은 신청하지 않을 수 있다. 소득은 선택한 구간만 공개할 수 있다. 이 조합을 지원하는 것이 추천안이며, 미증빙 사실을 편지에 담는 최종 표시 정책은 운영자 결정이 필요하다.

## 사용자 경험 배치 제안

1. **가입·진입:** 이용에 필요한 인증·동의와 최소 기본 정보를 받는다. 최소 항목은 전체 설계 확정 뒤 결정한다.
2. **갈피와 알아가기:** 생활 방식·성향·관계 의향을 점진적으로 이해한다. 사용자가 직접 정보 화면에서 추가·정정하는 길도 둔다.
3. **소개 준비:** 사진과 소개에 꼭 필요한 정보의 준비 상태를 확인한다. 조건·강점을 원하는 만큼 추가하고, 증빙과 공개 범위를 선택한다.
4. **내 소개 미리보기:** 실제 전달 형식으로 항목·표현·확인 표시를 검토한다. 공개하지 않은 항목은 빈칸이나 ‘비공개’ 목록으로 나열하지 않는 안을 추천한다.
5. **변경·갱신:** 정보 수정·공개 해제·증빙 재확인을 지원한다. 이미 전달된 편지에 변경을 어떻게 반영할지는 전달 시점 정책으로 별도 결정한다. 공개 해제가 상대의 기존 열람 기억까지 지운다고 약속하지 않는다.

## 인증·보관 운영 제약

- 현행 설계는 조건 증빙 원본을 확인 뒤 폐기하고 항목·구간·확인일 등 결과만 보관하는 방향이다. 접수 중 보관 기간·실패 시 삭제·접근 권한·처리 주체는 인증 방식 선택 때 구체화한다.
- 얼굴 사진·신분 확인·조건 서류의 처리를 하나로 묶지 않는다. 인증 업체·자동 판독·사람 검수 중 무엇을 쓸지 아직 정하지 않았다.
- 인증을 선택할 수 없는 사람이나 미등록자를 전체 노출에서 불리하게 만들지 않는다. 개인별 선호에 쓰는 범위와 전체 사용자 등급·순위를 구분한다.
- 새 외부 인증 서비스의 제공 범위·비용·정확도는 미확인이다. 선택 전 실제 자료를 조사하며 유료 호출·계정 생성은 별도 승인받는다.

## 결정 순서

1. 최종 정보 영역과 누락 여부를 확인한다. 현재 확정은 조건 정보의 선택 등록·선택 공개와 사진 수집 시점이다.
2. 소개 준비에 꼭 필요한 정보와 선택 정보를 구분한다. 특히 혼인 상태·관계 의향·생활 방식의 필수 범위를 결정한다.
3. 조건 정보의 공개 표시를 정한다: 직접 입력도 공개하고 확인된 항목에만 표시할지, 특정 항목은 인증 후 공개할지.
4. 인증 범위·방식·갱신 주기·보관을 정하고 화면에 배치한다. 이 결과로 가입 구성안을 갱신한다.
