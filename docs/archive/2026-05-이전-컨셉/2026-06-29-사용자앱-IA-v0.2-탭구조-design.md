## 1. 왜 다시 설계하나

- 빌드된 IA는 v0.1 문서 IA를 실용적으로 **압축**했다: 다단계 온보딩 일부 생략, 프로필 8단계→1화면, 추천 카드·상세·리포트→1화면, 매칭 순간 화면 부재, 홈 하단 **이중 내비**, 탭 화면에 불필요한 "뒤로" 등.
- v0.1 IA는 빌드 전 가설이었다. 빌드를 직접 보며 **"새로 설계(빌드 경험 반영)"** 하기로 결정(2026-06-29).
- 이번 패스는 그 출발점인 **하단 탭 구조**를 재정의한다. (진입·온보딩 IA / 화면 내 위계 / 디자인 시스템은 후속 패스)

## 2. 제품 정체성 — 이번 모든 결정의 토대

- **CONCEPT-1 (정체성)**: 프롤로그의 상수는 **큐레이션·품질·비상품화**다. "느림"은 컨셉이 아니다 — **속도는 사용자가 돌리는 유료 다이얼**이다. 기본값은 신중(무료 하루 3장), 원하면 본인이 가속.
- **CONCEPT-2 (외모)**: 외모는 **추천에 반영하되**(스킵/관심 등 행동 신호, 기존 `SkipReason.appearance_low_match` 활용) **남을 평가하는 기능은 두지 않는다.**
- 선택된 노선: "느리지만 다른" 제품(i). "이야기 향만 입힌 일반 데이팅 앱"(ii)으로의 피벗은 거부.

## 3. 탭 구조 v0.2

```
[1 추천]   [2 이야기 반응]   [3 관심]   [4 대화]   [5 마이]
```

| 탭 | 정체성 | 핵심 내용 | 현 빌드(4탭) 대비 |
|---|---|---|---|
| **1 추천** | 오늘의 큐레이션 | 오늘 추천 카드 + 유료 추가 카드. 카드 = "책 표지" | 현 홈 + 결제(추가 추천권) 연동 |
| **2 이야기 반응** 🆕 | 약한 신호 레이어 | 익명 이야기 조각 피드에 "이 글이 좋았어요" 반응 + 내 글에 반응한 사람 확인 → 관심으로 가는 진입로 | **신규 탭** |
| **3 관심** | 강한 신호 | 보낸 관심 + 받은 관심 | 현 관심탭은 '보낸'만. **'받은'은 신규** |
| **4 대화** | 매칭 후 대화 | 대화 목록·대화방 | 유지 |
| **5 마이** | 내 공간 | 마이페이지 + **내 책 가꾸기**(프로필=책 편집/보관) | 프로필 편집을 책 메타포로 통합 |

## 4. 신호 깔때기 & 안전

```
TAB-2 이야기 반응(익명)
  → 상호 반응 시 신원 공개         ← 새로 생긴 "약한 신호" 단계
  → TAB-3 관심(사람 전체, 강한 신호)
  → 매칭
  → TAB-4 대화
```

- **FUNNEL-1**: 기존엔 "관심(강)" 위에 약한 신호 단계가 없었다. TAB-2가 그 빈칸을 채운다. 약한 신호의 대상은 **외모가 아니라 글**이라는 점이 핵심 차별점.
- **SAFETY-1**: TAB-2의 상호작용은 **자유 대화 채널이 아니다.** 대화는 여전히 **상호 매칭 후에만** 열린다(F01 매칭 → 안전 안내 → 대화방). 반응/상호반응은 관심으로 가는 따뜻한 맥락일 뿐, 매칭 전 DM을 만들지 않는다.

## 5. TAB-2 "이야기 반응" 상세 방향 (구조 수준 결정)

- **메커니즘 = X (둘러보기 피드)**: 익명 이야기 조각을 둘러보며 반응. 단, 아래 4조건으로 "스와이프 피드"가 되지 않게 한다.
  1. **글 우선·얼굴 아님** — 피드의 단위는 사진 카드가 아니라 *이야기 조각(글)*.
  2. **긍정 반응만** — "이 글이 좋았어요" 한 방향. 좌우 스와이프/별점/거절 없음.
  3. **유한·큐레이션된 묶음** — 무한 스크롤 금지. "오늘의 이야기들" 같은 하루치 한정.
  4. **반응 비공개** — 공개 카운트·랭킹 없음(BRAND-1).
- **TAB-2-a 공개 시점**: **서로 반응할 때 신원 공개.** 익명으로 반응 → 양쪽이 서로의 글에 반응하면 그때 신원이 드러나고, 상대 책(프로필) 열람 → 관심 단계로 진입.
- **TAB-2-b 콘텐츠·동의**: 피드에 도는 글이 실제 사용자 답변이므로, **"내 이야기를 피드에 노출할지/어느 범위까지" 공개 범위 동의 정책을 신설**한다. (`prologue_04_privacy_visibility_policy` 갱신 대상)

> 상세 화면 UX(피드 화면, 공개된 상태 표현, 반응→관심 전환 동선)는 **별도 집중 패스**에서 설계한다(아래 §8).

## 6. 비즈니스 모델 원칙 (TAB-1/2/3과 직결)

| | 내용 |
|---|---|
| **MON-1 결제 경계** | 팔아도 됨: 추천 처리량/속도, 부가 편의(상세 리포트·대화 연장). 팔면 안 됨: 남에게 더 노출되기·매칭 보장·무료 사용자의 핵심 루프 배제 |
| **MON-2 무료 기본선** | **프로필 전체 열람·읽기·판단·매칭은 항상 무료.** 이야기가 제품의 영혼이므로 "읽고 판단하는 행위"는 유료화하지 않는다 |
| **MON-3 반응 공개** | **"내 글에 반응한 사람"은 무료로 공개.** 과금은 처리량/속도로(틴더식 "누가 좋아했나 보기" 유료 후크 = 결핍 자극이라 거부) |
| **품질 한도** | 속도는 "있는 품질 안에서"만 당긴다. 자격 후보 없으면 돈 받아도 억지 추천 금지(빈 상태 반환) |

## 7. 브랜드 / 메타포

- **BOOK-1**: **프로필 = 책** (표지=대표사진+한 줄 / 목차=이야기의 목차 / 본문=나의 프롤로그). 앱 전체 카드·상세의 시각 언어. "내 책 가꾸기/보관"은 TAB-5 마이에 위치.
- **BOOK-2**: 책방 메타포는 **공간·분위기**에만 ✅. **거래 동사(대여·반납·품절·장바구니·소장)는 사람에 금지 ❌.** "대여점" → "서재/열람실".
- **BRAND-1**: 반응은 비공개. 공개 카운트·인기 랭킹 없음(사람 순위표 금지).

## 8. 현 빌드 대비 변경 요약 & 후속 패스

**구조 변경 (개발 영향, high-level — 상세 분해는 별도 plan):**
- 4탭 → **5탭**, TAB-2 "이야기 반응" 신규.
- TAB-3 관심에 **받은 관심** 추가.
- TAB-5 마이에 **프로필=책 편집/보관** 통합(현 profile-edit 재배치).
- 홈 **하단 이중 내비 제거**, 루트 탭의 불필요한 "뒤로" 제거.

**열린 항목 (후속 결정 필요):**
- TAB-2 상세 UX 설계(익명 피드 화면, 공개 상태, 반응→관심 동선) — **별도 집중 패스**.
- 받은 관심: 무료 공개 vs Plus 차별화(현 코드 주석상 P2/Plus 후보) — MON 정책과 함께 결정.
- 탭 최종 이름(사용자 노출 카피) — 톤 가이드 통과 후보 작성.
- `privacy_visibility_policy`에 **이야기 피드 공개범위 동의** 항목 추가.
- 본 설계를 공식 `08_화면목록_IA v0.2`로 반영.

**이번 패스 이후 큰 그림 (순서):**

2. 진입·온보딩 IA 재설계 (온보딩 스택 일관화, 매칭 순간 화면 신설)
